RTX 3090 (24GB)에서 로컬 LLM 최적화 — ollama → vLLM 전환기

RTX 3090 24GB 단일 GPU에서 Qwen3 27B 비검열 모델을 vLLM으로 구동해

클라우드 모델에 밀리지 않는 로컬 LLM 환경을 구축한 기록. Hermes 환경에서 실사용.

여정 (Main Post + Reply Thread)

1. 시작 — ollama

  • LLM 구축 지식 0에서 시작. 놀고 있던 3090 활용.
  • 누구나 그렇듯 ollama로 시작 → 초당 50 tok 정도.
  • MTP(Multi-Token Prediction) 붙이니 40~50 tok, 최적화하니 60~80 tok.

2. ollama(llama.cpp)의 벽

  • 멀티 세션 불가 — 다른 일 처리 중이면 다른 세션이 대기.
  • 서브에이전트 호출 불가 — 1 스트림이라 요청이 들어오면 줄서기.
  • "로컬 LLM은 쓸데없구나" 하고 버릴 뻔함. 이게 제일 큰 문제였음.

3. 해결책 — vLLM

해결책은 vLLM입니다. 대박임. 아주 만족!!
  • 아래 설정값(카드)대로 AI에게 부탁하면 알아서 설치/구성해 줌.
  • 리눅스 환경 기준. 윈도우는 미검증.

왜 vLLM인가? — 엔진 비교 (Card 01/03)

RTX 3090 24GB · Qwen3.8 27B (W4A16) 실측

  • llama.cpp: 64 tok/s vs vLLM: 111 tok/s
  • 멀티세션 동시 처리 — 6개 시퀀스 동시(max-num-seqs=6), llama.cpp는 1 스트림만
  • Continuous Batching — prefill/decode 혼합 배치. 다른 요청이 와도 기다리지 않음
  • PagedAttention — KV 캐시 블록 관리. 131K 컨텍스트에서 메모리 파편화 0
  • OpenAI API 네이티브 — /v1/chat/completions, /v1/models. 어떤 클라이언트든 즉각 연결

엔진 전환 4가지 이유 (Card 02/03)

ollama (llama.cpp) → vLLM 0.27.1

#이유내용
1멀티 에이전트 동시 구동4개 Hermes 프로필(default, 토크맨, 스리부캐, 슈퍼맨)이 동시에 이 모델을 씀. llama.cpp는 1 스트림이라 교대 대기
2MTP Speculative Decoding내장 3-token MTP로 acceptance rate 2.4 — llama.cpp엔 이 경로가 없음. 실제 생성 속도 40% 향상
3Prefix Caching동일 시스템 프롬프트 재사용 시 TTFT 11.7s → 1.3s (9배). llama.cpp는 매 요청마다 full prefill
4비전(4K) + 131K 컨텍스트VLM tower + fp8 KV + max-num-seqs 6. llama.cpp는 4K 이미지 + 장문 컨텍스트 동시 처리가 OOM이나 극저속

배지: vLLM 0.27.1 · MTP ×3 · Prefix Cache

주의사항 / 팁

  • open webui 쓰지 말 것 — ollama 설치 시 딸려오는 open webui는 도구(tool)가 없어서 모델이 멍청해지고 웹 자료도 못 가져옴.
  • 세션 처음 시작할 때만 느리고(툴 로딩), 로딩 후엔 날아다님.
  • 설정값을 AI에게 주고 "설치해줘" 하면 알아서 구성됨 (Hermes 환경 기준).
  • 리눅스 검증 완료, 윈도우 미검증.
