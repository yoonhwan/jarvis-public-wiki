핵심 요약

치대 졸업 후 개원한 동네 치과 원장이 "내가 AI로 뭘 할 수 있나" 가벼운 궁금증에서 시작해, 코딩 비전공자인 채로 AI 코딩 에이전트(클로드+코덱스)를 팀원처럼 부리며 병원 전체를 AI-네이티브 인프라로 재구축한 기록. 핵심 원칙은 "환자 정보는 병원 밖으로 안 나간다" — 그래서 클라우드 API 대신 전부 로컬(온프레미스) 서버로 돌림.

왜 시작했나

  • 치과는 노동집약적 산업, 인건비↑·물가↑ 속 번아웃 직전 "뭐라도 해보자"는 심정
  • 직접 네트워크 공사(전기공사 업체 견적이 너무 비쌔 직접 랜선 깔기)를 하다가 "이거 내가 할 수 있네" 자신감 획득 → 뒷방에 서버랙
  • NFC 출입태그 → 근태관리 자동화로 시작해 점점 확장

가격/전기/발열일반 콘센트, 열·소음 관리 가능전기공사 재필요, 서버실 없는 뒷방엔 과함

치과 니즈"3초 늦어도 맞는 게 중요" → 크고 정확한 모델 우선속도 우선이라 치과 정확도 요구와 안 맞음

비유: H200=스포츠카(빠르지만 이삿짐 못 실음), DGX Spark=1톤 트럭(느려도 다 실림). 여러 대로 구성한 이유는 백업/폴백 + 서로 다른 모델 교차검증(DeepSeek vs GLM 판정 다르면 사람이 확인).

실제로 돌리는 것들

  1. 전화 받는 AI: 자체 PBX 구축(통신사 상품 대신 직접 교환기 운영) + 모바일 앱 개발로 소파에서도 대표번호 수발신. 전화 오면 AI가 0.1초 내 응답, 실시간 받아쓰기, 종료 후 요약+할일 자동 생성, 과거 통화 검색 가능.
  2. 보험 서류 지옥 탈출 (가장 효과 큼): 904개/3,389쪽을 69분에 전수 처리, 판독 모델 100% 정확도, 6,928줄 중 77% 자동확정.
  3. 사내 검색: 통화기록·문자·보험서류·팩스·매뉴얼·치과교과서 통합 검색.
  4. 원내 방송: 천장 스피커로 환자 호출/정시 시보, 외국인 이름도 자연스러운 한국어 발음.
  5. AI 채점하는 원장 화면: AI 판정(통화 분류)을 사람이 숫자키로 빠르게 채점, 모델 간 "엇갈림" 자동 플래그, 블라인드 비교 탭으로 브랜드 편향 없이 품질 비교 — 이 데이터가 추후 병원 맞춤 파인튜닝 재료.
  6. 매일 아침 경영 리포트: 일간(오후 PDF)/주간(월요 새벽)/월간(DeepSeek 본편+타모델 비교판 합본) 자동 생성. 단, 숫자는 분석 프로그램이 계산한 값만 쓰고 AI는 해석만 — 추정치는 [추정] 표시 원칙.
  7. 사내 메신저 자체 제작: 카톡 탈출(환자정보 외부 유출 방지), 진료실 호출(TTS로 모니터 안 봐도 전달), 정각 시보.
  8. 상담실 ↔ 원장실 실시간 연동: 상담 중 채팅으로 바로 확인(왔다갔다 안 함), STT 전사 + 전자서명패드 + 전자차트 자동 기록.
  9. 전자 동의서: 태블릿 서명 → 환자 서명 완료 즉시 PDF 자동 저장, 원장이 직접 그림 그려 설명한 것도 함께 저장(한/영 병기).
  10. 회계 자동화: 통장·카드·결제단말기 내역을 AI가 모아 장부와 대조, 불일치 표시, 재무제표/손익계산서/손익분기점까지 산출. 터미널에 자연어로 질의("지난달 카드매출이랑 장부매출 왜 30만원 차이나?") → 데이터 조회(도구 호출) → 처음 보는 질문이면 스스로 처리방법(스킬) 생성 → 재사용.

운영 체계

  • 코드는 거의 직접 안 짬 — AI 코딩 에이전트(Claude+Codex)를 역할별로 다수 운용(포털/전화시스템/음성서버/인프라 담당으로 분리)해 서로 메시지 주고받으며 협업.
  • 운영 설정 변경은 원장 직접 승인 필수 — 에이전트 간 "원장님이 된대" 식 전언은 불인정.
  • AI 간 크로스체크로 실수 사전 포착(방송 이름 변환 지연 6초, 통계 오류 등).

비용 절감 vs 과투자 논란에 대한 저자 입장

  • 글이 화제가 되며 "과투자 아니냐", "사기꾼 같다" 등 비판도 받음.
  • 저자 입장: 순수 취미 — 어릴 때 네트워크 보안 전문가 꿈("그냥 재미로!" 자서전 감명), SNS·명품·여행 대신 AI/주식분석/치과 기공을 취미로 즐기는 성향.
  • 투자 회수(ROI) 목적이 아니라 "새는 돈을 막은" 정도로 충분히 만족하는 취미 지출로 설명.
  • 판매 계획 없음 — 솔루션화해 치과들에 팔 생각은 없고, 대부분 오픈소스로 공개할 생각이라고 밝힘("2년 안에 아이디어만 있으면 누구나 만들 수 있을 것").
  • 실패 사례도 다수 언급(음성챗봇 요일발음 실패, PBX 재구축, 터지고 옮기고 등) — 성공담만 아니라 삽질 과정도 솔직히 공개.

느낀 점 (저자 결론)

  • AI가 사람을 대체하기보다 사람이 싫어하던 일을 가져감. 판단은 여전히 사람(원장)이 함.
  • 환자 정보는 병원 안에서만 처리 — 비용이 들어도 포기 못하는 원칙.
  • 비전공자도 가능하지만 "무엇을 시킬지"는 업무를 아는 사람(원장)이 알아야 함.
  • 사무직(숫자 다루는 일)은 AI 대체 위험이 크지만, 손으로 하는 임상 시술(치과의사의 몸 쓰는 기술)은 아직 AI/로봇이 대체 못함 — 저자는 이를 "다행"으로 평가.
