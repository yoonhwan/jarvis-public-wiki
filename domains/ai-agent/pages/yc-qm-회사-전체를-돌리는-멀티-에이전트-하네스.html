YC QM — 회사 전체를 돌리는 멀티 에이전트 하네스

YC가 새 소프트웨어를 공개하며 설치 안내를 딱 한 줄 남겼다: "코딩 에이전트한테 '이 레포를 배포해'라고 시키세요."

핵심 요약

  • 어제 YC가 내부에서 쓰던 멀티 에이전트 하네스 QM(여러 에이전트를 실제 업무에 붙여 돌리는 실행 틀)을 MIT 라이선스로 공개
  • 공개 15시간 만에 조회수 100만(1M) 돌파
  • 개인 비서가 아니라 회사 전체를 겨냥한 물건 — 에이전트에게 시키는 단위가 개인에서 조직으로 이동
  • 이름 QM = quartermaster(갑판 아래에서 물자·질서를 챙기는 직책)의 약자

본문 (Main Post)

1. 회계·법무·이벤트·엔지니어링 전부 에이전트로 돌린다

기존 에이전트 대부분은 개인 비서용 → 한 사람엔 잘 붙지만 회사에 붙이면 금세 복잡. QM은 처음부터 스타트업 단위로 설계:

  • 직원마다 자기만의 격리 워크스페이스
  • 사람과 방 하나하나에 메모리, 파일, 권한, 크론, 샌드박스가 따로 부착
  • 혼자 쓰던 설정 그대로 Slack 채널·프로젝트에 들어가 같이 일함

YC는 실제로 회계·법무·이벤트·엔지니어링을 이 위에서 돌리며, QM을 고치는 작업도 QM 안에서 한다.

2. Hermes 50대를 돌리다 한계 → QM 탄생

첫 시도가 아님. 진화 과정:

단계내용
1세대Ruby로 짠 단순한 루프 + 내부 데이터 읽는 툴 몇 개. 쓸모는 있지만 할 수 있는 일이 좁음
2세대크론·웹훅 트리거를 붙여가며 버팀
3세대개인용 오픈소스 에이전트 OpenClaw 등장 → 방향 전환
4세대직원 개인 비서로 Hermes 에이전트 50대+ 배포. 유연했으나 규모 관리가 버거워짐
최종목표 재정의: "Hermes만큼 유연하되, 처음 시스템만큼 단순하게" → 그 답이 QM

3. 코어는 하나, 하네스는 갈아 끼운다

  • 모든 요청이 중앙 코어를 거침
  • 코어를 Pi, OpenCode, Codex, Claude Code 네 하네스가 구동 → 마음에 안 들면 교체. 특정 벤더에 묶이지 않겠다는 설계
  • (재미있는 점: 출발점이던 Hermes는 이 목록에 없음)

보안 모드 3단계:

모드동작
Strict툴 호출을 사실상 전부 사람 승인에 걸어둠
Auto (기본값)외부 데이터·툴 결과를 분류기가 먼저 거른 뒤 모델에 넘김
Dangerous검사도 정지도 없음
단, 재귀 삭제·파괴적 SQL 같은 위험 명령은 어느 모드에서든 미리 정한 정책이 차단.

4. 설치 문서가 사람을 향하지 않는다

  • 공식 배포 절차: qm init 명령으로 배포용 스킬 생성 → 그 스킬을 에이전트한테 넘김
  • 인프라 설정·로그인 구성·커넥터 연결·배포·검증까지 에이전트가 진행
  • 레포에 .claude/skills, .codex/skills 폴더가 처음부터 포함
  • 이 소프트웨어의 첫 독자는 사람이 아니라 에이전트

5. 맺음말

QM을 몇 달째 가장 많이 썼다는 YC 직원의 말:

"우리는 일부러 말도 안 되게 작은 팀으로 남아 있는데, 아웃풋은 군대처럼 나온다."

YC 스스로 이 프로젝트를 실험(experiment)이라 부르며 초기 단계·버그 존재를 인정. 그러나 자기 회사를 통째로 올려 굴려본 다음 공개했다.

"다음 소프트웨어는 여러분이 설치하지 않습니다. 여러분의 에이전트가 설치합니다."
