27B 모델을 8GB로 — 도구 호출은 오히려 상승, 수학은 17점 하락

작성자: @aientrepreneur (AIpreneur)

원문: https://www.threads.com/@aientrepreneur/post/DeYtwLOGJmf

본문 (Main Post)

27B 모델을 8GB로 줄였더니, 도구 호출은 원본보다 잘하고 수학은 17점 떨어졌습니다.

Underdog «Saluki 27B»(허깅페이스, Apache 2.0). Qwen3.8-27B 54GB → 7.89GB.

  • 도구 호출 120문항: 88 (원본 84)
  • 병렬 호출: 42 (원본 35)
  • SWE-bench 50건: 30 (원본 33)
  • AIME 2025: 79.2 (원본 96.7)

«평균 96% 유지»는 평균이라 추론 손실이 가려집니다. 전부 제작사 측정, 원본 수학 점수는 다른 환경.

댓글 스레드 (Reply Thread — 작성자 추가 내용)

출처: ConwayResearch/Underdog-Saluki-27B-1.0 모델카드 (huggingface.co) — 카드 직독, 직접 실행은 안 했습니다. 카드 스스로 «120문항은 작은 시험, 몇 문항 차이는 실행마다 흔들림»이라고 적어 뒀어요.

핵심 요지: 도구 호출/병렬 호출/지시 이행(IFEval·IFBench)은 오히려 원본보다 높게 나왔으나, 수학 추론(AIME)과 MuSR(복잡 추론)에서 큰 손실. 양자화가 "추론/수학"을 특히 많이 깎아낸다는 전형적 패턴 — "평균 96% 유지" 홍보 문구는 이 비대칭 손실을 가린다는 게 작성자의 포인트.

실행 방법 (Quickstart)

huggingface-cli download ConwayResearch/Underdog-Saluki-27B-1.0 \
  Underdog-Saluki-27B-1.0-IQ2-mix.gguf --local-dir .

llama-server -m Underdog-Saluki-27B-1.0-IQ2-mix.gguf --jinja -ngl 99 -fa on -c 32768
  • --jinja: Qwen3.8 chat template 활성화 (tool call + thinking 지원)
  • 서버는 OpenAI chat API 포맷으로 포트 8080에서 응답
  • 일반 용도: thinking on(기본), temperature 0.6, topp 0.95, topk 20
  • 빠른 도구 호출: thinking off ("chattemplatekwargs": {"enable_thinking": false}), temperature 0
