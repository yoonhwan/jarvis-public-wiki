Memvid — AI 에이전트 메모리의 SQLite

AI 에이전트에 기억력을 주려면 보통 벡터 DB를 띄우고, 임베딩 서비스를 연결하고, RAG 파이프라인을 조립합니다. Memvid는 이 모든 걸 .mv2 파일 하나로 대체합니다.

Source: github.trending@Threads

핵심 개요

  • BM25 전문 검색 + HNSW 벡터 검색 + 임베딩 + 메타데이터 전부 단일 .mv2 바이너리 파일 안에 내장
  • 서버 불필요 — 완전 임베디드/서버리스
  • 텍스트, PDF, 엑셀, 오디오 입력 지원
  • Rust 코어 + Python / Node.js SDK 제공
  • 라이선스: Apache-2.0

핵심 비유: "AI 에이전트 메모리의 SQLite"

PostgreSQL 대신 SQLite를 쓰듯, Chroma/Qdrant/Weaviate 같은 벡터 DB 서버 대신 .mv2 파일 하나를 쓴다.

  • 파일 복사 = 에이전트의 전체 기억 복제
  • 이메일로 전송 가능
  • Git으로 버전 관리 가능
  • 서버 기반 메모리 시스템에서는 불가능한 일

진화 과정

버전방식특징
V1Python — 텍스트를 QR코드로 변환 → MP4 저장바이럴은 됐지만 실용성 낮음
V2Rust 완전 재작성커스텀 바이너리 포맷, 하이브리드 검색, 크래시 복구 → 프로덕션급

.mv2 파일 구조

4KB 헤더
→ 내장 WAL (Write-Ahead Log)
→ 데이터 세그먼트 (zstd/LZ4 압축)
→ 인덱스 세그먼트
→ 푸터
  • 모든 쓰기: append-only (크래시 안전성 보장)
  • 읽기: memmap2 zero-copy 메모리 매핑
  • 동일 입력 → 바이트 단위 동일 출력 (결정론적 구조)

Memvid 한계

  • 현재 단일 writer만 지원 (멀티 에이전트 동시 쓰기 불가)
  • 네트워크 공유 메모리 기능은 직접 구현 필요

이런 분께 추천

  • 에이전트에 장기 기억을 붙이고 싶은데 벡터 DB 운영이 부담인 개발자
  • 엣지/오프라인 환경에서 AI를 돌리는 팀
  • RAG 파이프라인 복잡도에 지친 분
  • 에이전트 메모리를 Git처럼 버전 관리하고 싶은 분
멀티 에이전트 동시 쓰기나 팀 간 실시간 메모리 공유가 핵심이라면 서버 기반 솔루션이 더 적합
