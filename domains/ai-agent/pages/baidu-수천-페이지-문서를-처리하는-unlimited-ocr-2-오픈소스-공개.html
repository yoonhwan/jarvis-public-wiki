핵심 요약

Baidu가 긴 문서를 한 번에 파싱하는 OCR 모델 Unlimited OCR 2 를 공개했다. 핵심 기술은 SR-SWA 로, 디코딩할 때 참조하는 토큰을 고정 크기(예: 512)로 묶어 문서가 길어져도 메모리와 지연이 거의 일정하게 유지된다. 라이선스는 MIT.

본문 (Main Post) — @choi.openai

Baidu가 수천 페이지 분량의 문서를 처리할 수 있는 Unlimited OCR 2를 오픈소스로 공개했습니다.
핵심은 SR-SWA와 Unlimited-Horizon Decoding 기술인데요.
문서를 여러 구간으로 나누고, 이전 구간의 마지막 페이지 정보만 유지하면서 불필요한 메모리를 비우는 방식입니다.
표가 여러 페이지에 걸쳐 있거나 문단이 다음 페이지로 이어지는 경우도 처리합니다.
100페이지 문서 기준 처리 속도는 최대 7배 빨라졌고, 캐시 메모리 사용량은 47GB에서 1.77GB로 줄었다고 합니다.

항목내용
SR-SWA (Sparse Reference Sliding Window Attention)텍스트·비전 attention 상호작용을 고정 크기 참조 집합(예: 512 토큰)으로 압축. 문서 길이와 무관하게 스텝당 지연·메모리가 거의 일정
Long → Unlimited-Horizon Parsing유한한 컨텍스트 창 안에서 문서 길이 제한 없는 파싱. 제곱 attention 증가와 메모리 병목 제거를 목표로 함
벤치마크MPDocBench(수십 페이지)와 MarathonDocBench(수백 페이지)에서 SOTA라고 주장. MarathonDocBench는 2026/10/27 신규 공개

SGLang 서버 주요 설정 (README 기준)

변수·옵션값의미
SGLANGUOCRDOCGUNDAMPAGEWINDOW / ...BASEPAGEWINDOW10윈도우당 페이지 수. 이전 윈도우의 KV tail을 재사용
SGLANGUOCRMAXPAGETOKENS20000페이지당 출력 상한
--mem-fraction-static0.70.75는 동시 요청 32개 이상에서 여유 부족
--max-prefill-tokens20484096 → 2048로 임시 텐서 피크가 절반
--port10000기본 서빙 포트

주의: 윈도우를 작게 잡으면 피크 메모리는 줄지만, 윈도우 경계를 넘는 블록은 문맥을 잃어 페이지 병합 품질이 떨어진다.
