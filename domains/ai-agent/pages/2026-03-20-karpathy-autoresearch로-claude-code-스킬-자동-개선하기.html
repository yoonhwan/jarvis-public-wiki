요약

Andrej Karpathy의 autoresearch 루프를 Claude Code 스킬에 적용하여, 스킬이 밤새 스스로 개선되는 방법을 소개한 글.

핵심 구조

  1. eval.json에 25개 참/거짓(binary) 테스트 작성
  2. 루프 실행 → 점수 오르면 커밋, 내리면 롤백 → 반복
  3. 프롬프트 한 줄: "사람이 멈출 때까지 절대 멈추지 마라"

실제 결과

  • 마케팅 카피 스킬에 적용 → 두 번 만에 만점 달성
  • 구조, 포맷, 단어 수 같은 규칙은 자동화 가능
  • 톤이나 창의성 판단은 여전히 사람 몫

Autoresearch for Skills — 작동 방식

대부분의 스킬은 ~70% 성공률. 나머지 30%를 없애는 방법:

핵심 루프 (5단계)

1. 스킬로 출력 생성 (테스트 입력 사용)
2. 모든 출력을 eval 기준으로 점수 매기기
3. 스킬 프롬프트를 변형(mutation)
4. 점수 오르면 유지, 내리면 폐기
5. 반복 (사용자가 멈출 때까지)

시작 전 필수 수집 정보

항목설명
Target skill최적화할 SKILL.md 경로
Test inputs3~5개 다양한 테스트 시나리오
Eval criteria3~6개 binary(yes/no) 체크 항목
Runs per experiment변형당 실행 횟수 (기본 5)
Run interval실험 주기 (기본 2분)
Budget cap최대 실험 횟수 (선택)

Eval 작성 규칙 (핵심!)

  • 반드시 binary (yes/no) — 1~7 스케일 금지 (분산 너무 큼)
  • 구체적으로 — "읽기 좋은가?" ❌ → "모든 단어가 잘리거나 겹치지 않는가?" ✅
  • 3~6개가 적정 — 많으면 스킬이 eval 통과에만 최적화됨
  • 게임 가능한 eval 금지 — "200단어 이하" → 간결함만 추구하게 됨

Eval 품질 체크 (3문 테스트)

  1. 두 에이전트가 같은 출력을 보고 동일하게 점수를 매길 수 있는가? → 아니면 너무 주관적
  2. 스킬이 실제 개선 없이 eval만 통과할 수 있는가? → 그렇다면 너무 좁음
  3. 이 eval이 사용자가 실제로 신경쓰는 것을 테스트하는가? → 아니면 삭제

실험 루프 상세

1. 실패 분석 → 어떤 eval이 가장 많이 실패하는지 확인
2. 가설 수립 → 하나만 변경 (5개 동시 변경 금지!)
3. 변경 적용 → SKILL.md 편집
4. 실험 실행 → 동일 테스트 입력으로 N회 실행
5. 점수 산출 → 전체 eval 점수 계산
6. 판정 → 개선=유지, 동일/하락=폐기(롤백)
7. 기록 → results.tsv + changelog.md
8. 반복

좋은 변형(mutation) 예시:

  • 가장 많이 실패하는 eval에 대한 명시적 지시 추가
  • 모호한 지시를 구체적으로 재작성
  • "하지 마라(Do NOT)" 안티패턴 추가
  • 묻힌 지시를 상단으로 이동 (우선순위 = 위치)
  • 정확한 행동을 보여주는 예시 추가

나쁜 변형 예시:

  • 전체 스킬 재작성
  • 10개 규칙 동시 추가
  • "더 좋게 만들어"같은 모호한 지시

출력물

autoresearch-[skill-name]/
├── dashboard.html       # 라이브 브라우저 대시보드 (10초 자동갱신)
├── results.json         # 대시보드 데이터
├── results.tsv          # 실험별 점수 로그
├── changelog.md         # 변형 상세 기록
└── SKILL.md.baseline    # 최적화 전 원본 백업

예시: 다이어그램 생성 스킬 최적화

실험점수변경 내용결과
0 (baseline)80%원본 그대로번호 매김 3건, 밝은 색상 2건, 읽기 어려운 텍스트 3건

인사이트

  • Karpathy의 ML 훈련 코드 최적화 방법론을 프롬프트 최적화에 적용
  • 핵심은 binary eval + 1변수 통제 + 자율 반복
  • "사람이 멈출 때까지 멈추지 않는다" — 에이전트 자율 루프의 정수
  • 스케일(1~7) 대신 binary(yes/no)를 쓰는 이유: 분산 최소화 → 신뢰할 수 있는 신호
  • 과적합 경계: eval을 6개 이상 넣으면 스킬이 eval 통과에만 집중
