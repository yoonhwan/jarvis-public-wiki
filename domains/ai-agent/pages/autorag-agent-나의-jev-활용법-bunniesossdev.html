요약

작성자가 만든 개인용 사서 에이전트 AutoRAG Agent에서 Jev(판단 전용 모델)를 5곳에 쓰는 방법을 소개한 글이다. 핵심은 "에이전트 루프에 들어가기 전과 후에 Jev가 판단만 맡는다"는 구조다.

본문 (Main Post)

나의 Jev 활용법

#용도내용
1라우팅에이전트 루프에 들어가기 전에 로컬 검색인지, 일반 작업인지, 설정 변경인지 분기한다
2답변 검증먼저 빠른 답을 낸다. 그 답이 충분한지 판단하고, 부족하면 에이전트가 추가로 탐색한다
3인용 검증LLM이 엉뚱한 근거를 인용하는 일이 있다. 문장·질의·근거를 Jev에 넣어 근거가 뒷받침하는지 판단한다
4메모리 관리그럴듯하지만 쓸모없는 데이터가 메모리에 쌓인다. 저장 전에 Jev로 검증한다
5실행 승인 게이트"뭐 다들 하시죠?" (작성자 코멘트, 설명 없음)

이 모든 것이 적용된 개인용 사서 에이전트가 AutoRAG Agent다. "빠르게 당신의 파일들을 다 뒤져서 정보를 찾아내요."

  • 링크 프리뷰: GitHub - Marker-Inc-Korea/AutoRAG: Your Personal Librarian Agent. Ask anything on your computer, organize files, remember important info and files.
  • 이미지/카드: 없음 (텍스트 포스트)
  • 댓글 스레드: 작성자 추가 답글 없음. 다른 사용자 직접 댓글은 수집 시점에 보이지 않음.
  • 참여 수치 9 / 1 / 9는 라벨 없이 출력되어 의미를 확인하지 못함 (좋아요/댓글 등으로 단정하지 않음).

항목내용비고
정체AutoRAG 2.0. 사무용 개인 사서 에이전트기존 Python AutoRAG(RAG AutoML)는 legacy/로 이동, 유지보수 모드
런타임Pi agent framework 위에서 동작단일 모델이 검색·직접 읽기·정리를 맡음
라이선스Apache-2.0
요구 환경Node >= 24, Bun >= 1.2npm 패키지 @autorag/librarian
형태CLI, TUI(autorag tui), TypeScript 라이브러리, MCP 서버(Lite), 데스크톱 앱

핵심 원칙 3가지

  1. 데이터를 옮기지 않는다. 업로드·ETL·중앙 vector DB 없이 데이터가 있는 곳에서 그대로 질의한다(in-place federation).
  2. 설정이 거의 필요 없다. 파이프라인 튜닝, vector DB 관리, 원격 embedding 키가 필요 없다. MinSync가 증분 CDC chunking을 처리하고 로컬 embedding backend를 기본 제공한다.
  3. 빠르게 동작한다. 다중 에이전트 계층 대신 단일 모델이 전체 루프를 맡는다.

아키텍처 5개 서브시스템

#서브시스템역할
1Retrieval Memory (check_memory)답변 뒤에 Jev가 "실제로 뒷받침한다"고 판단한 인용 근거만 ~/.autorag/memory.json에 저장. 이후 검색에 참고용(advisory)으로만 제공
2다중 검색SPLADE sparse, 의미(vector), hybrid, Jikji find-first, 파일명 검색(Everything/FSearch), datasource skills
3Result Merger방식 간 중복 제거, 점수 정규화, 범위 좁히기
4Direct Evidence Readingbash의 cat/grep/find로 유망한 파일을 직접 열어 사실 확인
5Curation최종 답변의 인라인 [eN] 인용을 번호가 붙은 근거 링크로 변환

Jev의 역할 (README 기준)

README의 Jev Decisions 항목은 Jev를 필수(required) 판단 모델로 설명한다. 작성자 글의 5가지 활용과 README 설명이 겹치는 부분은 다음과 같다.

작성자 글README 대응
라우팅질문을 local search / extra(지식 답변·기타 작업) / organize(파일 이동·이름 변경·정리) / config 분기로 보냄. 신뢰도 하한 0.75
답변 검증빠른 답변(fast answer)을 먼저 내고, 그 답이 완전하면 거기서 종료. 아니면 verification 단계 진행
인용/메모리 검증근거가 답을 뒷받침한다고 Jev가 판단한 경우만 memory에 저장
  • Jev는 다중 질문을 최대 5개 병렬 검색으로 나누는 단계, 검색할 datasource를 고르는 단계 앞에서도 쓰인다.
  • Jev 백엔드: dazzi(기본 모델 jev-1.13), openrouter, openai, typesafe, vercel-ai-gateway, cloudflare-workers-ai, opencode. autorag models list --decision으로 후보를 확인한다.
  • 첫 질문마다 Jev 응답을 점검한다. 응답이 없으면 sLLM fallback으로 넘어가고, 그것도 실패하면 decision-model-unavailable(exit 3)로 멈춘다.
  • 호스팅 플랜: Dazzi Models. TUI에서 /login으로 로그인(API 키 환경변수 없음).

빠른 시작 (README 기준)

# 설치 (Node.js 24 이상 또는 Bun)
bun install -g @autorag/librarian    # 또는 npm install -g @autorag/librarian

# 문서 폴더 지정
autorag init --search-paths ~/Documents/research

# 색인 → 상태 확인
autorag refresh
autorag status

# 검색, 인터랙티브 TUI
autorag search "질문"
autorag tui
init/refresh/status는 README Quick Start 절 그대로다. search와 tui는 README의 CLI 절에 나온 명령이다. 첫 실행 시 chat model 1개와 Jev가 필요하다. TUI에서 /login과 /model로 설정하고, Jev는 Dazzi Models 로그인 또는 OPENROUTERAPIKEY로 쓴다.
