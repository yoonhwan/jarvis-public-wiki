설치 이유 (openclaw_ko 후속 댓글)

OpenClaw 사용 시 장기기억으로 저장하더라도 중요한 내용과 아닌 것을 구분하기 어려워 전부 저장하게 됨. 그러면 나중에 기억을 불러올 때 입력 토큰값이 어마어마해지는 문제 발생.

@asin_cartel 님이 이를 압축하여 토큰 값을 90% 이상 줄일 수 있도록 개발한 것이 Oc-Memory.

유사 오픈소스 비교

Oc-Memory와 같은 "AI 에이전트 장기 기억 + 대화 압축" 접근을 하는 주요 오픈소스들:

🥇 Letta (구 MemGPT) — 가장 완성도 높은 메모리 프레임워크

  • GitHub: https://github.com/letta-ai/letta (⭐ 30K+)
  • 접근: OS처럼 메모리를 계층 관리 (core memory = RAM, archival = 디스크)
  • 핵심: sleep-time compute로 유휴 시간에 자동 요약/압축
  • 특징: 에이전트가 스스로 메모리를 관리, .af 포맷으로 상태 이식 가능
  • vs Oc-Memory: 범용 프레임워크라 세팅 복잡. 기능은 훨씬 풍부하지만 OpenClaw 전용이 아님

🥈 Mem0 — 가장 실용적인 메모리 레이어

  • GitHub: https://github.com/mem0ai/mem0
  • 접근: 대화 전체 압축 대신 핵심 사실만 선택적 저장 (memory formation)
  • 핵심: 벡터 검색 + 지식 그래프 + 시멘틱 인덱싱
  • 효과: 토큰 80-90% 절감, 응답 품질 26% 향상 (자체 벤치마크)
  • vs Oc-Memory: 코드 한 줄 통합 가능. 요약이 아닌 "핵심 사실 추출" 방식이 다름

🥉 Zep — 프로덕션 레벨 메모리 서버

  • GitHub: https://github.com/getzep/zep
  • 접근: 별도 서버에서 대화 히스토리 자동 요약 + 엔티티 추출
  • 특징: LangChain/LlamaIndex 통합 지원, 엔터프라이즈 지향
  • vs Oc-Memory: 대규모 서비스에 적합. 개인용 OpenClaw에는 오버스펙

📌 기타 주목할 만한 것들

  • KVzip (NVIDIA): KV 캐시 레벨에서 3-4배 압축, 정확도 유지 (2025년 최신)
  • LangChain Memory: ConversationSummaryMemory 등 플러그인 방식 메모리 모듈
  • Awesome-Memory-for-Agents (칭화대): 메모리 관련 논문 모음 — https://github.com/TsinghuaC3I/Awesome-Memory-for-Agents

우리 OpenClaw 메모리 전략 분석

현재 설정 (2026-02-13 기준)

  • contextPruning: cache-ttl 모드, TTL 1시간
  • compaction: safeguard 모드
  • session-memory 훅: 활성화 (세션 간 메모리 플러시)
  • heartbeat: 1시간 간격
  • 메모리 구조: memory/YYYY-MM-DD.md (일별) + MEMORY.md (장기)

Oc-Memory가 해결하는 우리의 문제

  1. 일별 메모리 파일 누적: 매일 memory/YYYY-MM-DD.md가 쌓이면 시간이 지날수록 컨텍스트 토큰 증가
  2. MEMORY.md 수동 관리: 현재 하트비트에서 수동으로 정리하지만 자동화 부재
  3. 옵시디언 노트 활용: jarvis-vault의 방대한 노트들을 메모리로 활용하지 못함

적합한 개선 방향

1단계 (즉시 가능) — Oc-Memory 도입

  • 감시 폴더: ~/Library/Mobile Documents/iCloud~md~obsidian/Documents/jarvis-vault/ (옵시디언 vault)
  • 메모리 동기화: ~/.openclaw/workspace/memory/로 압축 동기화
  • 효과: 옵시디언 노트들이 자동으로 OpenClaw 메모리에 반영

2단계 (최적화) — 메모리 리뷰 자동화

  • 크론 잡으로 주간 메모리 리뷰 자동화
  • 오래된 일별 파일 → MEMORY.md로 자동 정리
  • 30일 이상 된 일별 파일 아카이브

3단계 (심화) — Mem0 스타일 사실 추출 검토

  • 단순 요약이 아닌 핵심 사실/결정/선호도 자동 추출
  • 구조화된 메모리 (태그, 카테고리별 분류)
  • 옵시디언 세컨드브레인과 양방향 연동
