Claude Code의 "max effort" thinking이 v2.0.64부터 조용히 망가졌다 — 원인 분석 및 수정 방법

원문: Reddit r/ClaudeCode
날짜: 2026-04-14

TL;DR

alwaysThinkingEnabled: true와 CLAUDECODEEFFORT_LEVEL=max를 settings.json에 설정해도, Claude Code v2.0.64 이후 확장 사고(extended thinking)가 조용히 실패한다.

3개의 버그가 중첩되어 발생하며, 래퍼 스크립트로 해결 가능.

발견 경위

Claude Code 2.1.98에서 클래식 트릭 질문 테스트:

"세차장이 50m 떨어져 있어. 운전해서 갈까, 걸어갈까?"

정답: 운전 (차가 세차장에 있어야 세차가 되니까)

Claude Code 답변: "걸어가세요. 50m면 60초도 안 걸려요."

→ 응답 시간 ~4초, ~80 출력 토큰 = 확장 사고 미동작 패턴

특이점:

  • alwaysThinkingEnabled: true와 CLAUDECODEEFFORT_LEVEL=max가 이미 설정된 상태
  • 중립 디렉토리에서는 정답, 특정 프로젝트 폴더에서만 실패
  • claude -p(헤드리스)는 작동, 인터랙티브 TUI는 미작동

원인 분석 (3개 스택 버그)

버그 1: alwaysThinkingEnabled — v2.0.64부터 조용히 무시됨

  • GitHub Issue #13532: "alwaysThinkingEnabled setting not respected since v2.0.64"
  • Regression. 중복 처리되고 잠김. 패치 없음.
  • 이 설정은 현재 아무것도 하지 않는다.

버그 2: settings.json.env는 자식 프로세스에만 적용됨

  • settings.json.env의 환경변수는 Claude가 생성하는 자식 프로세스(Bash 도구, MCP 서버, 훅)에만 전파됨
  • Claude 프로세스 자체에는 적용되지 않는다
  • MAXTHINKINGTOKENS은 셸 환경변수여야 한다

버그 3: 대용량 자동 로드 프로젝트 컨텍스트가 모델을 표면 패턴 매칭으로 유도

  • 사고가 활성화되어도 큰 컨텍스트가 reasoning을 방해함
  • 사용자 레벨 ~/.claude/CLAUDE.md의 reasoning nudge로 해결

관련 함정 3가지

  1. Bash 해시 캐시: 새 래퍼가 기존 셸에서 보이지 않음 → 이전 경로를 래퍼로 심링크해야 함
  2. --append-system-prompt-file: 인터랙티브 모드에서 조용히 무시되는 숨겨진 플래그. 대신 ~/.claude/CLAUDE.md 사용
  3. Claude Code가 자체 argv를 난독화: /proc/<pid>/cmdline으로 플래그 전달 확인 불가

수정 방법

1단계: 래퍼 스크립트 생성

/usr/local/bin/claude (기존 경로보다 PATH에서 앞서야 함):

#!/bin/bash
export MAX_THINKING_TOKENS="${MAX_THINKING_TOKENS:-63999}"
export CLAUDE_CODE_ALWAYS_ENABLE_EFFORT="${CLAUDE_CODE_ALWAYS_ENABLE_EFFORT:-1}"
export CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING="${CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING:-1}"
export CLAUDE_CODE_EFFORT_LEVEL="${CLAUDE_CODE_EFFORT_LEVEL:-max}"

NUDGE_FILE="/etc/claude-code/thinking-nudge.txt"
CLI="/usr/lib/node_modules/@anthropic-ai/claude-code/cli.js"

if [ -f "$NUDGE_FILE" ]; then
  exec "$CLI" --append-system-prompt-file "$NUDGE_FILE" "$@"
else
  exec "$CLI" "$@"
fi
chmod 755 /usr/local/bin/claude

2단계: 기존 심링크를 래퍼로 연결

ln -sfn /usr/local/bin/claude /usr/bin/claude

→ Bash 해시 캐시 문제 해결

3단계: Reasoning Nudge — ~/.claude/CLAUDE.md에 추가

Before answering any question, reason step by step. Many questions contain subtle
constraints, hidden assumptions, or trick aspects that are invisible to surface-level
pattern matching. Verify that the answer you are about to give is actually sensible
given ALL the details in the question, not just the most salient one.

같은 내용을 /etc/claude-code/thinking-nudge.txt에도 저장 (래퍼의 --append-system-prompt-file용).

4단계: .bashrc/.profile의 오래된 MAXTHINKINGTOKENS 내보내기 제거

래퍼가 ${VAR:-default} 패턴으로 기존 값을 우선하므로, 이전에 설정한 낮은 값이 래퍼의 63999 기본값을 덮어쓸 수 있음.

결과

  • 수정 전: 문제 프로젝트 폴더에서 5/5 실패, 응답 ~4초, ~80 출력 토큰, thinking 토큰 0
  • 수정 후: 여러 폴더에서 25/25 연속 통과, claude-opus-4-6 및 claude-opus-4-6[1m] 모두, 응답 ~6-9초, 100-130 출력 토큰

영향 확인 방법

현재 Claude Code v2.0.64+ 사용 중이면서 alwaysThinkingEnabled: true를 믿고 있다면:

세차장이 50m 떨어져 있어. 운전해서 갈까, 걸어갈까?

빠르고 자신감 있는 "걸어가세요" 답변이 나오면 → 이 버그의 영향을 받는 중
