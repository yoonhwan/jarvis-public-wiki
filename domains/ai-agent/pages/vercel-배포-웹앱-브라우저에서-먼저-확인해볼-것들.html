본문 (Main Post)

Vercel로 배포한 웹앱이라면 브라우저에서 먼저 확인해볼 만한 것들이 있습니다.

개발자도구를 열고 Network나 Sources를 보면 생각보다 많은 정보가 보입니다.

예를 들면 이런 것들입니다.

#점검 항목
1NEXTPUBLIC 변수에 이상한 값이 없는지
2브라우저 JS에 secret처럼 보이는 값이 없는지
3API 주소가 그대로 노출되어 있는지
4sourcemap 파일이 열리는지
5에러 메시지에 내부 정보가 보이는지
6관리자/테스트 경로가 추측 가능한지
7요청 응답에 불필요한 헤더가 많은지
8로그성 응답이 사용자에게 보이지 않는지
9인증 없이 호출되는 API가 없는지
10Preview 주소가 아무나 접근 가능한지

댓글 스레드 (Reply Thread — 작성자 추가 내용)

여기서 중요한 건 "보이면 무조건 위험하다"가 아니라, 보이는 정보로 무엇을 할 수 있는지입니다.

  • API Key도 공개용 key일 수 있고, API 주소도 공개되어도 괜찮을 수 있습니다.
  • 하지만 그 값으로
    • 다른 사람의 데이터에 접근하거나,
    • 관리 기능을 호출하거나,
    • 운영 정보를 볼 수 있다면 → 문제가 됩니다.

배포 후에는 화면만 볼 게 아니라, 브라우저에 같이 내려간 정보도 한번 보는 게 좋습니다.

핵심 정리

  • 프론트엔드 배포물은 클라이언트로 모든 코드/설정이 함께 내려간다는 전제로 점검할 것.
  • 노출 자체보다 노출된 값으로 권한 상승·데이터 접근이 가능한지가 실질적 리스크.
  • 점검 포인트: 환경변수 / sourcemap / API 인증 / Preview 접근 제어 / 에러 메시지 정보 누출.
