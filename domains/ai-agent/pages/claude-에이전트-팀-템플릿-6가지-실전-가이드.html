핵심 요약

Anthropic 공식 데모 6종을 분석하고 산업별 에이전트 팀 템플릿 6가지를 직접 구성/테스트한 실전 가이드.

핵심 인사이트:

  • Agent Teams는 "독립 작업 + 소통" 구조
  • 서브에이전트 = 심부름꾼, Agent Teams = 팀원
  • 역할 분리 + 최소 도구가 성공의 핵심
  • 리드는 sonnet, 워커는 haiku로 비용 80-90% 절감

Agent Teams vs Subagent

항목SubagentAgent Teams
컨텍스트메인과 공유각자 독립
소통 방식결과만 반환직접 메시지 교환
조율메인이 관리자체 조율 (공유 태스크)
적합한 작업단순 위임복잡한 협업

언제 뭘 쓰나?

  • 50-100줄 단위 스킬/에이전트 → Subagent (가성비 최고)
  • 대형 프로젝트 (여러 역할 협업 필요) → Agent Teams

공식 데모 6종 분석

1. Research Agent (Python) - 가장 완성도 높음

Lead Agent (haiku)
├── Researcher x4 (병렬)
│   ├── tools: WebSearch, Write
│   └── files/research_notes/*.md 저장
├── Data Analyst x1
│   ├── tools: Glob, Read, Bash, Write
│   └── matplotlib 차트 생성
└── Report Writer x1
    ├── tools: Skill, Write, Glob, Read, Bash
    └── reportlab PDF 생성

실행 결과: 7분 54초, 82회 도구 호출, 비용 약 $0.05-0.10 (haiku)

핵심 패턴:

  • Lead는 Task 도구만 (직접 일하지 않고 지시만)
  • 각 에이전트는 필요한 도구만 부여
  • 파일 기반 소통 (files/ 폴더 저장 → 다음 단계 읽음)

2. Email Agent (TypeScript) - MCP 연동의 정석

  • React + Express 웹앱
  • WebSocket 실시간 통신
  • MCP 도구명을 직접 tools 배열에 추가 가능
    • mcpemailsearch_inbox
    • mcpemailread_emails

교훈: Slack, GitHub, DB 등 어떤 MCP 서버든 에이전트에 연결 가능

3-6. 나머지 데모

데모언어핵심

Chat AppReact + ExpressSDK 웹앱 통합 레퍼런스
Hello World V2TypeScriptSession API (멀티턴, 세션 재개)

산업별 템플릿 6가지

상세 프롬프트는 [[templates.md]] 참고

1. 코딩 팀 (풀스택 개발)

  • Lead Architect (sonnet) + frontend/backend/test/reviewer (haiku)
  • 핵심: 폴더 단위 역할 분리로 충돌 방지
  • reviewer는 Read 전용 (Write 주면 오히려 꼬임)

2. DevOps 팀

  • infra-engineer, ci-cd-specialist, monitoring-agent, security-scanner
  • 참고: cc-devops-skills

3. 데이터 분석 팀

  • collector → analyst/ml-engineer (병렬) → report-writer
  • 공식 Research Agent와 동일 구조

4. 콘텐츠 팀 (블로그/마케팅)

  • researcher → writer (sonnet!) → editor → seo → sns
  • ⚠️ writer는 반드시 sonnet (haiku는 품질 저하)

5. 고객 지원 팀

  • ticket-classifier → knowledge-searcher → response-drafter → escalation-handler

6. 투자 분석 팀

  • market-scanner, fundamental/technical/news-analyst, risk-manager, report-generator
  • 저자의 @forge 에이전트 실전 구조

비용 최적화 전략

전략설명절약 효과
모델 선택리드만 sonnet, 워커는 haiku80-90%
도구 제한필요한 도구만 부여불필요 호출 방지
프롬프트 최적화간결하고 구체적 지시20-30%
병렬 실행독립 작업 동시 실행시간 50% 단축
파일 기반 캐싱중간 결과 파일 저장반복 작업 제거

비용 비교:

  • 전원 haiku: $0.05-0.10 (~8분)
  • 리드 sonnet + 팀원 haiku: $0.20-0.50 (~7분) ⭐ 추천
  • 전원 sonnet: $0.50-1.00 (~6분)
  • 전원 opus: $5-10 (~5분)

활성화 방법 3가지

1. settings.json (권장)

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}

2. 마크다운 에이전트 파일

mkdir -p .claude/agents
# .claude/agents/reviewer.md
---
name: reviewer
description: "코드 리뷰 전문가"
tools: Read, Grep, Glob
model: haiku
---
# 리뷰어 지침
코드를 분석하고 개선 사항을 제안합니다.

3. SDK AgentDefinition (코드)

AgentDefinition(
    description="코드 리뷰 전문가",
    tools=["Read", "Grep"],
    prompt="코드를 분석하고 개선 사항을 제안합니다.",
    model="haiku"
)

git clone https://github.com/wshobson/agents.git
cp -r agents/.claude/* .claude/

실수하는 3가지

1. 도구를 너무 많이 줌

# ❌ 나쁜 예
researcher:
  tools: WebSearch, Write, Read, Edit, Bash, Grep, Glob

# ✅ 좋은 예
researcher:
  tools: WebSearch, Write

2. 모든 에이전트를 같은 모델로

  • 리드는 판단력 필요 → sonnet
  • 단순 작업자 → haiku
  • 전원 opus는 돈 낭비

3. 역할 경계가 불명확

# ❌ 나쁜 예
agent-1: "코드 작업합니다"

# ✅ 좋은 예
frontend-dev: "src/components/ 폴더의 React 컴포넌트만 담당"

해결책: 폴더 단위로 영역 나누기
