클로드가 쓴 한국어에서 AI 티를 걷어내는 도구가 나옴
잡는 건 이런 거임: 긴 줄표(—), 가운뎃점 나열, ~되어지다 같은 번역투

댓글 스레드 (Reply Thread, 작성자 pm_anyway 본인 연속 댓글 10개)

  1. 만든 사람은 긱뉴스의 leeandev. 클로드한테 회의록이나 보고서를 맡길 때마다 매번 손으로 고치다가, 그 규칙을 모아서 Claude Code 플러그인으로 공개함.
  2. 본문에 쓴 것 말고도 다 본 적 있는 것들을 잡음: ★랑 이모지, "~을 통하여", "React 와"처럼 조사 앞 띄어쓰기.
  3. 예시 문장:
      • 전: "본 과제는 … 사용 편의성을 제고하고 — 대여 절차를 간소화하는 것을 목표로 함"
      • 후: "사내 도서 대여 앱의 검색 구조를 바꿔 쓰기 편하게 하고 대여 절차를 줄이는 것을 목표로 함"
  4. 이 문장이 들어 있던 예제 문서에서 경고가 9개 떴는데, 고치고 나니 0개가 됨.
  5. 재밌는 점: 영어판을 그대로 옮기지 않음. 영어판 stop-slop의 핵심은 "능동태로, 짧게"인데 한국어 보고서에 쓰면 오히려 더 이상해짐.
  6. "정의함"이 "정의한다"로 바뀌기 때문. 한국어 보고서의 "~함, ~됨" 개조식은 AI 티가 아니라 원래 정상 문체. 그래서 다듬기 모드는 끝맺음을 건드리지 않고 부호와 번역투만 잡음.
  7. 가운뎃점도 다 잡는 게 아님. "성능·품질"처럼 붙여 쓴 건 한 단어처럼 쓰는 거라 그대로 둠. AI 티는 "A · B · C"처럼 띄어서 줄줄이 늘어놓을 때 남.
  8. 에세이/블로그 글은 옵션 하나 켜면 더 깐깐하게 봄: "~의 중요성을 깨달았다"식 교훈형 마무리, "~라고 생각한다" 반복, "또한"으로 시작하는 문단이 몰려 있는 것.
  9. 같이 든 도구도 결이 같음: 경영진/타팀용으로 글을 바꿔 쓸 때 원문에 없는 진척률은 지어내지 않고 "확인 필요"로 남김. 자소서도 대신 써 주지 않고 인터뷰로 경험을 꺼내 본인 말투로 초안을 씀.
  10. 그러니까 "~함, ~임"으로 끝나는 이 글은 AI 티가 아니라는 거임. (작성자 본인 유머)

스캐너 slop_scan.py

  • 사용: python plugins/stop-slop-ko/skills/stop-slop-ko/scripts/slop_scan.py 보고서.docx --info
  • 서술형 글은 --prose 옵션으로 추가 검사
  • exit code: 0 = PASS, 1 = FAIL(WARN 있음), 2 = 입력 오류
  • 스캐너가 못 잡는 것(상투구, 과한 명사화, 기계적 3단 병렬)은 스킬이 읽고 판단
  • --prose 신호: INFO는 교훈형 마무리, "단순한 ~이 아닌", 빈 강조어("정말", "매우") 등. WARN은 "~라고 생각한다" 3회 이상이면서 1,000자당 1회 이상, 연결어("또한", "나아가") 시작 문단이 3개 이상이면서 전체의 25% 이상. 글이 길수록 기준이 올라감
  • 요구사항: Python 3.8+, pptx 정제는 python-pptx, DOCX 출력은 python-docx

영어판 규칙을 그대로 쓰면 안 되는 이유 (README 요지)

  • ~함/~됨 개조식은 슬롭이 아니라 한국 공식문서의 정상 문체. 정제 모드는 종결어미를 바꾸지 않음
  • 한국어 슬롭 신호는 문장부호와 번역투: em-dash, 공백 가운뎃점 나열, ★, ~에 있어서, ~되어지다, 조사 앞 공백
  • 영어판의 "3항목 나열 금지", "not X but Y 금지"는 한국어 요구사항/스펙 열거에 적용하지 않음 (문체가 아니라 내용이므로)
  • 붙임 복합어(성능·품질)의 가운뎃점은 보존

자동 적용 훅

"회의록 만들어줘", "보고서 pptx로", "AI 티 빼줘" 같은 요청을 감지하면 스킬 사용을 안내. 청중이 정해진 요청("경영진용", "브리프")이면 stakeholder-brief를 먼저 안내. 요청에 "stop-slop 빼고"나 "원문 그대로"를 넣으면 개입하지 않음.
