카파시 LLM 위키 시스템 — RAG 없이 마크다운으로 지식관리

원본 Threads 포스트 | 상세 분석 글 | GitHub Gist (Karpathy)

핵심 요약

Andrej Karpathy (AI의 아버지, vibe coding 창시자)가 공개한 LLM Knowledge Base 시스템.

논문·기사·자료를 넣으면 AI가 알아서 마크다운 위키를 만들고, 기존 10~15개 문서를 업데이트하고, 백링크까지 자동 생성.

카파시 본인이 100개 문서, 40만 단어 규모로 실제 운영 중.

왜 RAG를 버렸나

  • RAG: 질문할 때마다 원본 문서를 새로 읽어야 함 → 비효율
  • LLM Wiki: 원본을 한 번 "컴파일"해서 구조화된 위키 생성 → 이후엔 위키에서 바로 꺼내씀
  • 복잡한 벡터 DB, 파이프라인 없음 — 마크다운 파일 + 폴더 + LLM이 전부

3-Layer 아키텍처

레이어역할관리자
Raw Sources논문, 기사, 이미지 등 원본 (불변)인간이 수집
Wiki마크다운 파일 — 요약, 개념 정리, 백링크LLM 전담
Schema위키 구조와 규칙 정의 (CLAUDE.md 등)인간+LLM 공동

워크플로우

  1. Data Ingest — 원본 자료를 raw/ 폴더에 투입
  2. LLM Compilation — LLM이 읽고 위키 페이지 생성/업데이트 (1 소스 → 10~15 페이지 영향)
  3. Active Maintenance — 주기적으로 전체 점검, 불일치 수정, 새 연결 생성

카파시 13년 원칙 (핵심!)

도구가 아닌 원칙이 변하지 않았다:

  • 능동적 참여 — 수동 소비 금지, 직접 읽고 이해한 뒤 LLM 활용
  • 구조화 — 이해된 지식을 체계화
  • 연결 — 문서 간 백링크로 지식 복리 성장

LLM은 이 원칙의 실행 비용을 극적으로 낮춰줄 뿐, 원칙 자체를 대체하지 않는다.

3단계 읽기법

  1. Pass 1: 직접 읽기
  2. Pass 2: LLM에게 설명/요약 요청
  3. Pass 3: LLM과 Q&A

수동 읽기가 먼저 — LLM은 능동적 학습의 도구

왜 인간은 위키를 포기하나

"인간이 전통적 위키를 포기하는 이유는 유지보수 부담이 인지된 가치를 초과하기 때문이다." — Karpathy
  • Obsidian 사용자 150만+, 플러그인 2,700+
  • 하지만 꾸준히 유지하는 사람은 소수 → 디지털 쓰레기 문제

LLM의 해법: 피로 없음, 크로스 레퍼런스 자동 업데이트, 한 번에 15개 파일 수정 가능

→ 유지보수 비용 ≈ 0 → 가치가 항상 비용 초과 → 포기하지 않게 됨

실무 적용 시 주의사항

  • 분류 먼저: 문서 유형별로 다른 추출 전략 (토큰 절약 + 품질 향상)
  • 토큰 예산 설정: L0(~200) ~ L3(5-20K) 단계별 명시
  • 이중 출력 규칙: 모든 작업 = 직접 산출물 + 위키 업데이트 (둘 다 필수!)
  • 할루시네이션 주의: 출처 인용 강제, 정기 스팟체크, 인간이 편집장 역할 유지
  • 스케일 한계: 100개 문서 OK, 수만 개는 RAG 하이브리드 필요할 수 있음

자비스와의 연관성

이 시스템은 자비스의 현재 구조와 유사:

  • jarvis-vault = Wiki 레이어
  • MEMORY.md + memory/*.md = Compiled Knowledge
  • #threads-web-link 채널 = Data Ingest 파이프라인

확장 아이디어: raw/ 폴더 개념 도입 → 읽은 자료 자동 위키 컴파일 워크플로우
