PSA: Claude Code Has Two Cache Bugs That Can 10-20x Your Costs

Reddit r/ClaudeAI — Claude Code 바이너리 리버스 엔지니어링으로 발견한 2가지 캐시 버그. 비용 10~20배 증가 가능.

요약

작성자가 Claude Code standalone 바이너리(228MB ELF)를 Ghidra + MITM 프록시 + radare2로 리버스 엔지니어링하여 프롬프트 캐시를 무효화시키는 2개의 독립적 버그를 발견. 비용이 조용히 10~20배 부풀려질 수 있음.

Bug 1: Standalone 바이너리의 Sentinel 치환이 캐시를 깨뜨림

이슈: anthropics/claude-code#40524

  • Standalone Claude Code 바이너리 (claude.ai/install.sh 또는 npm install -g)에는 Anthropic 커스텀 Bun fork의 네이티브 레이어 문자열 치환이 존재
  • Zig HTTP 헤더 빌더 함수에 주입됨 (Content-Length, User-Agent 등과 동일 함수)
  • /v1/messages 요청 시 anthropic-version 헤더가 있으면 JSON 바디에서 cch=00000 (빌링 attribution sentinel)을 찾아 body 해시 기반 5-char hex로 치환
  • JSON.stringify 후, TLS 암호화 전에 실행 → JS에서 완전히 보이지 않음

문제 발생 조건

  • 대화 히스토리에 sentinel 문자열 리터럴이 포함될 때 (CC 번들 소스 읽기, 빌링 헤더 논의, CLAUDE.md에 포함 등)
  • messages[]가 system[]보다 먼저 직렬화되므로, messages 내의 sentinel이 먼저 치환됨
  • → 매 요청마다 messages content 변경 → 캐시 프리픽스 깨짐 → 풀 캐시 리빌드

워크어라운드

# standalone 대신 npx로 실행
npx @anthropic-ai/claude-code
  • 치환 메커니즘은 커스텀 Bun fork에만 존재
  • npm 패키지를 표준 Bun/Node에서 실행하면 치환 없음 (실험 확인)

Bug 2: --resume이 항상 캐시를 깨뜨림 (v2.1.69+)

이슈: anthropics/claude-code#34629

  • 모든 --resume이 대화 히스토리 전체의 캐시 미스를 유발
  • 시스템 프롬프트(~11-14k 토큰)만 캐시되고, 나머지는 cache_creation부터 재시작

근본 원인

v2.1.69에서 deferredtoolsdelta 도입:

상태messages[0]위치
Fresh session~13KB (4 reminders: deferred tools + MCP + skills + AU$)messages[0]
Resume~352B (AU$ context만)messages[0], 나머지는 messages[N]

3가지 독립적 캐시 깨짐:

  1. messages[0] 크기/내용 완전히 다름
  2. system[0] 빌링 해시 변경 (첫 user message의 4, 7, 20번째 문자 기반)
  3. cache_control breakpoint 위치 이동

워크어라운드

  • 외부 워크어라운드 없음
  • v2.1.68 또는 v2.1.30으로 다운그레이드하면 해결 (단, 60+ 버전의 기능 손실)

자비스 메모
