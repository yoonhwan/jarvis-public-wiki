핵심 요약

Vercel과 shadcn이 UI SDK를 공개했다. 컴포넌트 묶음이 아니라 행동(behavior) 라이브러리다. 버튼·셀렉트의 클릭 처리, 키보드 내비게이션, 포커스 이동, 팝업·선택 로직처럼 매번 다시 짜던 부분을 뽑아 재사용 가능한 단위로 만들었다. AI 에이전트가 예약 화면 같은 UI를 만들 때 이 동작들을 처음부터 구현하지 않아도 된다.

핵심 차이는 추상화의 위치다. shadcn은 발표문에서 "에이전트가 인터페이스의 생산자이자 사용자가 되고 있다. 그러면 추상화는 어디에 있어야 하나"라고 문제를 던진다. 답은 스타일이 아니라 동작이다. 마크업·디자인은 각 프로젝트가 가져가고, 동작과 접근성(ARIA)만 SDK가 제공한다.

본문 (Main Post)

이제 AI가 필요한 화면을 직접 만들어 사용하는 시대가 다가오고 있습니다.
Vercel과 shadcn이 UI SDK를 공개했는데요. 버튼이나 선택 메뉴의 클릭, 키보드 조작 같은 동작을 재사용할 수 있도록 분리한 개발 도구입니다.
예를 들어 AI가 예약 화면을 만들 때 메뉴를 선택하고 입력값을 처리하는 기능을 처음부터 구현할 필요가 없습니다.
개발 환경에 관계없이 활용할 수 있어, AI가 상황에 맞는 화면을 직접 만드는 데 도움이 될 것으로 보입니다.

발표 트윗은 스레드 형식이라 첫 트윗만 확보했다. 이하 내용은 공식 문서와 GitHub README로 보강했다.

GitHub README 보강 (vercel-labs/ui)

무엇을 파는가

A library of behaviors for agents to build the next generation of user interfaces.

키보드 내비게이션, 포커스, 선택, 닫기(dismissal), 팝업, 드래그 앤 드롭, 그리고 그 동작들이 필요로 하는 ARIA가 @ui-sdk/core에 들어 있고, React·Vue·Svelte·Solid·Web Components 어댑터가 그 위에 붙는다.

설치

npm install @ui-sdk/react @ui-sdk/core
# 다른 프레임워크는 @ui-sdk/vue / @ui-sdk/svelte / @ui-sdk/solid / @ui-sdk/web

에이전트에 스킬을 장착한다.

npx skills add vercel-labs/ui --skill ui-sdk

사용 방식 — primitive 정의 → 파트로 렌더

컴포넌트를 직접 쓰는 게 아니라 primitive를 정의하고, 그 primitive를 createParts로 각 프레임워크에 맞게 렌더한다. 검색 필드 예시를 요약하면 이렇다.

import { createFocusRecovery, definePrimitive } from "@ui-sdk/core"

const searchField = definePrimitive({
  name: "search-field",
  state: () => ({ value: "" }),
  api: (context) => ({
    set: (value: string) => context.store.set({ value }),
    recovery: createFocusRecovery({ fallback: () => context.element("input") }),
  }),
  slots: (slot) => ({
    input: slot({ /* value 바인딩 + input 이벤트 */ }),
    clear: slot({ /* 값이 있을 때만 노출, 클릭 시 초기화, 포커스 복구 */ }),
  }),
})
import { createParts } from "@ui-sdk/react/primitive"
import { searchField } from "./search-field"

const parts = createParts(searchField, { input: "input", clear: "button" })
const SearchField = parts.Root
const SearchFieldInput = parts.Input
const SearchFieldClear = parts.Clear

README가 강조하는 지점은 "이 코드를 사람이 배울 필요는 없다. 에이전트가 쓴다"이다. 즉 사람이 라이브러리를 익히는 게 아니라 에이전트가 규약대로 생성하는 것을 전제로 설계됐다.

컴포넌트는 이 행동들을 조합해서 만든다. 문서가 바로 제공하는 완성 컴포넌트 예시는 Select, Field, Tabs, Combobox, Date Picker, Menu다.

에이전트 온보딩이 문서의 1급 시민

Quickstart 첫 화면이 사람용 설명이 아니라 에이전트에 붙여넣는 프롬프트다. React 기준 프롬프트가 시키는 일은 세 가지다.

  1. @ui-sdk/react와 @ui-sdk/core 설치 (React 19 이상)
  2. AGENTS.md에 규칙 추가 — "ui-sdk를 쓰기 전에 설치된 ui-sdk 스킬을 따르고, node_modules/@ui-sdk/react/docs/llms.txt를 읽는다. 새 컴포넌트를 만들 때는 docs/core.md를 헤딩으로 검색하고 rendering.md를 함께 읽는다"
  3. npx skills add vercel-labs/ui --skill ui-sdk

즉 라이브러리가 패키지 안에 자기 문서(llms.txt)를 넣고, 에이전트가 그걸 읽고 조립하는 구조다. 사람용 API 레퍼런스보다 에이전트용 컨텍스트가 앞에 놓인다.

실무 판단 포인트

  • Beta다. API·문서·동작이 GA 전에 바뀔 수 있다고 README가 명시한다. 사내 프로덕션 핵심 화면에 바로 넣기보다 신규 화면·프로토타입부터 적용하는 편이 안전하다.
  • React 19 미만은 막힌다. React 18 기반 레거시 프로젝트는 어댑터 진입 자체가 안 되므로, 적용 검토 전에 런타임 버전을 먼저 확인해야 한다.
  • 에이전트 스킬 설치가 사실상 필수 경로다. 문서 Quickstart가 AGENTS.md 규칙과 스킬 설치를 전제하므로, 스킬을 안 붙이고 사람이 손으로 primitive를 쓰는 방식은 권장 경로가 아니다.
  • "동작만 가져온다"는 것이 실질 이득. 디자인 시스템이 이미 있는 팀은 마크업을 유지한 채 키보드·포커스·ARIA만 교체할 수 있다. 디자인 시스템이 없는 팀은 이득이 작다.
