Rust로 GPU 커널을 직접 구현해 기존 pyannote 대비 화자 분리 속도를 60배 끌어올린 speakrs가 공개되었습니다.

cuda-oxide를 활용해 작성된 이 도구는 동일한 RTX 4090 환경에서 전체 음성 인식과 화자 라벨링 속도 또한 WhisperX보다 17.7배 빠르게 처리합니다.

파이썬 중심이던 오디오 AI 파이프라인에서도 Rust 기반 커널 최적화가 압도적인 성능 차이를 보여주는 만큼 대용량 음성 처리 실무에 도입해 볼 만한거 같습니다.

핵심 요약

speakrs는 pyannote community-1 파이프라인(분할, 화자 임베딩, PLDA + VBx 클러스터링)을 Rust로 구현한 오픈소스 화자 분리 라이브러리다. 3주 전까지는 CUDA 모드가 ONNX Runtime 위에서 돌았다. 지금은 cuda-oxide(Rust로 GPU 커널을 쓰는 NVIDIA cuda-rust 프로젝트)로 직접 쓴 커널로 돌고, NVIDIA 드라이버만 있으면 빌드가 된다. 저자는 커널 코드 대부분을 AI 코딩 에이전트가 작성했고, 목표와 합격 기준(DER 악화 없음)은 자신이 정했다고 밝힌다.

cuda-oxide 사용 소감 (저자)

  • 장점: Rust 안에서 호스트 코드와 같은 타입으로 커널 작성, 생성된 PTX가 읽기 쉬움, FP32에서 cuDNN과 비트 단위 동일 결과(SincNet), PTX/cubin을 미리 빌드해 crate에 포함하므로 사용자는 안정(stable) Rust와 CUDA 툴킷 없이 사용 가능.
  • 거친 부분: 일부 intrinsic이 sm80 이상으로 제한(Turing은 ptxasm! 우회), 라이브러리 crate가 prebuilt 커널을 배포하는 공식 방법 없음, 텐서코어 코드는 대부분 raw PTX.
  • 저자 결론: "cuda-oxide is ready." 단, cuDNN/cuBLAS 완전 대체는 "대부분 가치 없음". GPU마다 새로 렌탈, 프로파일링, 튜닝이 필요하고 렌탈 비용은 약 $150. 사용자 GPU가 소수로 정해져 있거나 이미지 2GB 절감이 중요하지 않으면 라이브러리를 유지하고 느린 레이어만 커널로 쓰라고 권고.

driver-only 빌드

  • 예: speakrs = { version = "0.7", features = ["cuda-rtx40"] }
  • libcuda와 드라이버 PTX JIT만 열며 드라이버 570 이상 필요. cuDNN/cuBLAS 링크 없음(ldd, strace로 확인했다고 기술).
  • GPU 이미지에서 약 2GB 절감(cuDNN 9 약 1.2GB + cuBLAS 12 약 0.8GB).

에이전트 활용에서 얻은 교훈 (저자)

  • 증명 하네스(provably no slower)에 약 5일을 썼으나 그 기간에 머지한 PR은 1개(#36). 하네스를 버리고 "byte-identical RTTM 또는 DER 불변 + 고정 파일셋 RTFx 향상"이라는 단순 기준으로 바꾸자 이후 8시간에 더 많이 출시.
  • 새 GPU마다 반드시 프로파일링(소비자 카드에서 이긴 커널이 A100에서는 cuDNN보다 1.4배 느렸음).
  • 에이전트가 자기 스크립트 오타에도 멈춰서 기다리지 않게 할 것. GPU 렌탈 3건 1회에 $0.21.

  • 측정 조건: RTX 5090, 6개 영어 데이터셋 212개 녹음, 114시간.
  • 게시물의 "17.7배"는 이 dialogrs 결과다. speakrs 단독 수치가 아니다.
  • scriptrs(Parakeet TDT 0.6B v2/v3, ONNX Runtime/PyTorch 없이): RTX 5090, LibriSpeech test-clean RTFx 1534배, NeMo 대비 3.2배, ONNX Runtime 대비 6.1배, WER 1.93% 동일.
  • 저자는 저가 API를 곧 연다고 예고(이메일 사전 신청 중). 저자 자체 벤치마크이며 독립 검증은 확인하지 못함.

설치 (원문 기준)

# Rust
speakrs = { version = "0.7", features = ["cuda-rtx40"] }   # GPU를 알면
speakrs = { version = "0.7", features = ["cuda"] }         # 모르면 (cuDNN 폴백 포함)

# Python
pip install speakrs
import speakrs
pipeline = speakrs.Pipeline.from_pretrained("cuda")
print(pipeline.diarize_file("meeting.wav").rttm())
  • Python wheel: Linux x86_64는 CPU + CUDA, macOS arm64는 CPU + CoreML.
  • RTX 20 시리즈와 T4 이후 GPU 지원.

메모

  • 모든 성능 수치는 저자 본인의 측정이다. 독립 검증 [확인 필요].
  • 오빠 환경 관점: macOS(Apple Silicon)에서는 CoreML 경로만 해당. CUDA 경로는 NVIDIA GPU 서버(OCI/GPU VM)에서 쓰는 경우에 해당.
