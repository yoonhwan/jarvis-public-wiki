0. ⭐ GPU 서버 Self-hosted 운영 — 생성·목록·선택·삭제 (실제 사용 시나리오)

0-1. 구조 이해 — Qwen 공식 리포 vs 커뮤니티 서버 래퍼

Qwen 공식 GitHub(QwenLM/Qwen3-TTS)는 Python 라이브러리만 제공한다 — 상주 HTTP 서버나 "프로파일 저장/관리" 기능이 없다. 매번 스크립트를 실행해서 그 순간 결과만 얻는 구조. "GPU 서버에 올려서 관리"하려면 아래 중 하나를 얹어야 한다:

서버 래퍼특징프로파일 관리
groxaxo/Qwen3-TTS-Openai-Fastapi (권장)OpenAI 호환 /v1/audio/speech, Docker/NVIDIA GPU 지원, Gradio Voice Studio 포함(선택 마운트)✅ 생성·목록·로드·삭제 전부 지원 (파일시스템 + API. UI는 옵션)
vLLM-Omni 공식 예제 서버vllm-omni serve, OpenAI 호환 /v1/audio/speech, 처리량 최적화❌ 프로파일 개념 없음 — 매 요청마다 ref_audio 직접 첨부
QuaxelBrod/qwen3-tts-api단순 FastAPI, /profiles 엔드포인트로 CRUD✅ 생성·목록·삭제 (Docker, 소규모)

이하 groxaxo 래퍼 기준으로 정리 (기능이 가장 완전함, 225 stars).

⭐ UI 불필요 결정 (2026-09-03, 오빠 확인): 우리는 자체 서비스(프론트엔드)가 이미 있으므로 Gradio Voice Studio는 아예 배포하지 않는다. groxaxo 서버는 ENABLEVOICESTUDIO 환경변수가 기본값 false라서 아무 설정 안 하면 자동으로 꺼져 있음 — 별도 조치 불필요, 그냥 이 변수를 건드리지 않으면 됨. 아래 0-2~0-7 전부 순수 REST API 호출만으로 구성되어 있고, Voice Studio는 관리자가 수동으로 프로파일을 만들 때 쓰는 보조 UI일 뿐 API 기능과 100% 동일하다 — UI를 안 쓴다고 기능이 빠지는 건 없다.

0-2. 서버 기동 (GPU, UI 없이 API 전용)

git clone https://github.com/groxaxo/Qwen3-TTS-Openai-Fastapi.git
cd Qwen3-TTS-Openai-Fastapi
# Voice Clone(Base) 모델로 기동 — CustomVoice 모델은 클론 불가하므로 반드시 Base 계열
# ENABLE_VOICE_STUDIO를 아예 넣지 않으면 기본값 false → Gradio UI 자동 비활성
TTS_BACKEND=official \
TTS_MODEL_NAME=Qwen/Qwen3-TTS-12Hz-1.7B-Base \
VOICE_LIBRARY_DIR=/data/qwen-voices \
python -m api.main
# 또는 GPU Docker:
docker compose up --build qwen3-tts-gpu
  • http://<server>:8880/docs` — Swagger (API 스펙 확인용, UI 아님)
  • http://<server>:8880/v1/voices` — 등록된 프로파일 목록 확인
  • ⚠️ CustomVoice 모델(사전 정의 스피커) ≠ Base 모델(클론용) — 클론 프로파일을 쓰려면 서버가 Base 체크포인트로 떠 있어야 한다. TTS_BACKEND=optimized면 clone: 요청 시 자동으로 Base로 스위치해줌.
  • /voice-studio 경로는 ENABLEVOICESTUDIO=true를 명시적으로 켜야만 마운트됨 — 우리는 이 변수를 아예 설정하지 않으므로 이 경로 자체가 존재하지 않음 (attack surface 축소 효과도 있음).

0-3. 생성 (Create) — 새 목소리 프로파일 등록

A) API로 직접 클론 (1회성, 저장 안 됨):

import base64, requests
ref = base64.b64encode(open("reference.wav", "rb").read()).decode("ascii")
r = requests.post("http://<server>:8880/v1/audio/voice-clone", json={
    "input": "테스트 문장입니다.",
    "ref_audio": ref,
    "ref_text": "reference.wav에 실제로 녹음된 대사 원문",  # ICL 모드 필수
    "x_vector_only_mode": False,
    "language": "Korean",
})
open("out.wav", "wb").write(r.content)

B) Voice Library에 영구 저장 (진짜 "프로파일 생성"):

서버 파일시스템에 아래 구조로 직접 배치하거나, Voice Studio(Gradio, ENABLEVOICESTUDIO=true → /voice-studio)에서 업로드:

$VOICE_LIBRARY_DIR/profiles/
└── <프로파일명>/
    ├── meta.json      # {"name":"윤환","ref_audio_filename":"reference.wav","ref_text":"...","x_vector_only_mode":false,"language":"Korean"}
    └── reference.wav

저장 즉시 /v1/voices 목록에 clone:<프로파일명>으로 나타나며 재부팅 후에도 유지된다(디스크 영속).

0-4. 목록 조회 (List)

curl http://<server>:8880/v1/voices
{"voices": [

0-5. 선택 사용 / 기존 프로파일과 스위치 (실제 운영 방식)

별도의 "활성화" API는 없다 — 매 합성 요청의 voice 파라미터에 어떤 프로파일을 쓸지 그때그때 지정하는 stateless 구조 (아리클라우드 API와 동일한 패턴):

from openai import OpenAI
client = OpenAI(base_url="http://<server>:8880/v1", api_key="not-needed")

# 프로파일 A 사용
r1 = client.audio.speech.create(model="tts-1", voice="clone:윤환", input="첫 번째 문장")
r1.stream_to_file("out1.mp3")

# 같은 서버에서 프로파일 B로 바로 스위치 — voice 값만 바꾸면 됨
r2 = client.audio.speech.create(model="tts-1", voice="clone:상애", input="두 번째 문장")
r2.stream_to_file("out2.mp3")

# 사전 정의 스피커(클론 아님)로도 스위치 가능
r3 = client.audio.speech.create(model="tts-1", voice="Ryan", input="세 번째 문장")
  • 레퍼런스 오디오는 프로세스 메모리에 캐시(refaudiocache)되고, 스피커 임베딩도 캐시(voicepromptcache)되므로 같은 프로파일 재사용 시 임베딩 재계산 없이 빠름 (재계산 생략으로 약 0.7초 절약).
  • optimized 백엔드가 아니면 서버에 로드된 모델이 CustomVoice일 때 clone: 요청이 실패한다 — 자동 스위치 안 됨. TTS_BACKEND=optimized를 쓰면 clone: 요청 감지 시 Base 모델로 자동 전환.

0-6. 삭제 (Delete)

공식 REST 삭제 엔드포인트 문서는 명시되어 있지 않지만, 프로파일이 디스크 폴더 그 자체이므로:

rm -rf $VOICE_LIBRARY_DIR/profiles/<프로파일명>

또는 Voice Studio UI(/voice-studio)의 "Manage your voice library (view, load, delete profiles)" 메뉴에서 삭제 가능 — UI가 이 파일 삭제를 대행해준다.

0-7. 감정 태그 / 스타일 지시 (self-hosted 서버에서)

CustomVoice 계열(generatecustomvoice)엔 instruct 자연어 파라미터가 공식 지원:

r = client.audio.speech.create(
    model="tts-1", voice="Ryan", input="오늘 정말 신나요!",
    extra_body={"instructions": "아주 신나고 빠른 어조로"}
)

⚠️ 클론 음색(clone:프로파일명)에는 감정 지시 파라미터가 공식적으로 연결되어 있지 않음 — Base 모델(generatevoiceclone)은 GitHub 공식 API 시그니처상 instruct 인자를 받지 않는다. 감정 있는 클론이 필요하면 §5의 "VoiceDesign → Clone prompt" 우회 워크플로우를 self-hosted 환경에도 그대로 적용해야 한다 (레퍼런스 오디오 자체를 감정 실린 걸로 미리 만들어서 등록).

0-9. 사용자 多일 때 스토리지 — GCS로 교체 (2026-09-03 추가)

groxaxo 래퍼 기본값은 VOICELIBRARYDIR(로컬 디스크 폴더)에 profiles/<name>/{meta.json, reference.wav}를 저장한다. 소수 사용자면 문제없지만, 사용자 多 → 다음 이유로 GCS(또는 동급 오브젝트 스토리지)로 옮기는 게 맞다:

로컬 디스크 유지 시 문제GCS로 옮기면
GPU 서버 로컬 SSD 용량 한계, 서버 재배포/스케일아웃 시 프로파일 유실 위험서버는 stateless — 어느 GPU 노드에서도 같은 프로파일 접근 가능
GPU VM 여러 대로 오토스케일링 시 프로파일 동기화 불가 (서버 A에 저장한 게 서버 B엔 없음)모든 GPU 노드가 같은 GCS 버킷을 바라봄 — 동기화 문제 자체가 사라짐
백업/버저닝 직접 구현 필요GCS 버킷 버저닝/라이프사이클 정책으로 해결
사용자별 접근 격리(멀티테넌시)를 파일시스템 권한으로 억지로 구현GCS는 오브젝트 단위 IAM + Signed URL로 테넌트 격리가 자연스러움

권장 아키텍처 (일반적인 멀티테넌트 패턴):

[클라이언트] → [API 서버(FastAPI)] → 프로파일 메타데이터: Firestore/Cloud SQL (테넌트ID, 이름, ref_text, 생성일)
                                    → 레퍼런스 오디오 바이트: GCS 버킷 (gs://voice-profiles/<tenant_id>/<profile_id>/reference.wav)
                                    → 합성 요청 시: GCS에서 signed URL로 오디오 fetch → GPU 서버 로컬에 임시 캐시(LRU) → 임베딩 계산 → 폐기
  • 오디오 원본은 GCS가 SSOT, GPU 서버는 요청마다(또는 LRU 캐시로) 필요한 것만 로컬에 내려받아 씀 — groxaxo의 refaudiocache/voicepromptcache 인메모리 캐시 패턴을 GCS 소스와 결합하면 됨.
  • 메타데이터는 별도 DB(Firestore 등)로 분리 — GCS는 객체 조회에 최적화되어 있지 않아 "이 사용자의 프로파일 목록"류 쿼리는 DB가 담당하고 GCS는 blob 저장소 역할만.
  • 이 구조는 groxaxo 래퍼의 meta.json 로딩 로직을 커스텀 스토리지 백엔드로 교체하는 작업이 필요함 — 현재 코드베이스엔 GCS 어댑터가 기본 내장되어 있지 않으므로 직접 구현/포크해야 함 (공식 지원 아님, 확인 필요 시 groxaxo 이슈 트래커에 요청 가능).

0-10. 라이선스 확인 결과 — 커뮤니티 서버 래퍼도 Apache-2.0 (2026-09-03 확인)

오빠가 우려하신 "Voice Studio는 라이선스 이슈, 가중치가 Apache 아닐 수 있다" → 직접 라이선스 원문 확인 결과 둘 다 Apache-2.0이 맞다. 상세:

구성요소라이선스확인 방법
Qwen3-TTS 모델 가중치 (Qwen/Qwen3-TTS-12Hz-1.7B-Base 등)Apache-2.0HuggingFace 모델 카드 메타데이터 직접 확인 (license: apache-2.0) — 상업적 사용 명시적으로 OK, 별도 청원(청원식 게이트) 없이 즉시 다운로드 가능
Qwen 공식 GitHub 리포 (QwenLM/Qwen3-TTS, 코드)Apache-2.0LICENSE 파일 원문 확인 (Copyright 2026 Alibaba Cloud)
groxaxo/Qwen3-TTS-Openai-Fastapi (서버 래퍼, Voice Library 포함)Apache-2.0 (원본 Qwen 리포에서 fork, 자체 LICENSE 파일도 Apache-2.0)LICENSE 파일 원문 확인
Gradio Voice Studio (gradiovoicestudio.py, groxaxo 리포 내)같은 리포 소속 → Apache-2.0별도 라이선스 파일 없음 — 리포 루트 LICENSE 적용받음. Gradio 라이브러리 자체도 Apache-2.0

결론: Qwen3-TTS 계열(모델 가중치 + 코드)과 groxaxo 서버 래퍼(Voice Studio 포함) 전부 Apache-2.0으로 확인됨 — 오빠가 걱정하신 라이선스 이슈는 이 조합에선 발견되지 않았다. 단, 아래는 별개로 주의:

  • 다른 TTS 엔진과 혼동 주의: Sarashina-TTS, OuteTTS, Dia, Spark-TTS 등은 연구/개인용만 허용, 상업적 사용 불가 (Qwen3-TTS와 다름). Supertonic은 OpenRAIL-M(사용 기반 윤리 제약 — 딥페이크/사칭 금지 조항 있음). Qwen3-TTS를 명시적으로 계속 써야 라이선스가 안전하다.
  • 음성 복제 자체의 법적 리스크는 라이선스와 별개: Apache-2.0이 소프트웨어 사용을 허가해도, 타인의 목소리를 본인 동의 없이 복제/사칭하는 행위는 별도의 초상권·개인정보·사기 관련 법적 이슈가 될 수 있음 — 모든 프로파일은 본인 동의된 화자의 음성만 등록해야 함.
  • 라이선스는 시점 스냅샷(2026-09-03 확인) — 향후 Qwen 팀이 라이선스를 변경할 가능성은 이론상 있으나, 현재 배포된 가중치/코드에 소급 적용되지는 않음(Apache-2.0은 영구·취소불가 라이선스).

1. 개요 — 모델 계열 2종

百炼(Bailian) 플랫폼에는 음성 복제를 지원하는 서로 다른 모델 계열 2개가 있으며, API의 model 파라미터 값과 액션명이 다르다. 혼동 주의 — 동일 엔드포인트(POST .../audio/tts/customization)를 쓰지만 페이로드 스키마가 다르다.

2. 음성 복제(Voice Clone) 운영 — 생성·조회·관리·삭제

2-1. 생성 (Create)

Qwen-Audio-TTS/CosyVoice (voice-enrollment, 공개 URL 필요):

curl -X POST 'https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/audio/tts/customization' \
  -H "Authorization: Bearer $DASHSCOPE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "voice-enrollment",
    "input": {
      "action": "create_voice",
      "target_model": "qwen-audio-3.0-tts-flash",
      "prefix": "myvoice",
      "url": "https://your-audio-url.wav",
      "language_hints": ["zh"],
      "enable_volume_normalization": "false"
    }
  }'

→ 응답: {"output": {"voice_id": "qwen-audio-3.0-tts-flash-myvoice-xxxxxx"}}

Qwen-TTS (qwen-voice-enrollment, Base64 or URL):

import os, requests, base64, pathlib

api_key = os.getenv("DASHSCOPE_API_KEY")
audio_b64 = base64.b64encode(pathlib.Path("voice.mp3").read_bytes()).decode()
data_uri = f"data:audio/mpeg;base64,{audio_b64}"

resp = requests.post(
    "https://dashscope.aliyuncs.com/api/v1/services/audio/tts/customization",
    headers={"Authorization": f"Bearer {api_key}", "Content-Type": "application/json"},
    json={
        "model": "qwen-voice-enrollment",       # 고정값
        "input": {
            "action": "create",
            "target_model": "qwen3-tts-vc-2026-01-22",   # 합성 시 반드시 동일 모델 사용
            "preferred_name": "guanyu",           # 숫자/영문/언더스코어, 16자 이내
            "audio": {"data": data_uri}
        }
    }
)
voice_id = resp.json()["output"]["voice"]

→ 응답: {"output": {"voice": "yourVoice", "target_model": "..."}, "usage": {"count": 1}}

핵심 제약: target_model은 복제 시 지정한 값과 합성(TTS) 호출 시 반드시 동일해야 함 — 다르면 합성 실패.

2-2. 목록 조회 (List — 프로파일 여러 개 선택할 때 사용)

curl -X POST '.../audio/tts/customization' \
  -H "Authorization: Bearer $DASHSCOPE_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-voice-enrollment",
    "input": { "action": "list", "page_size": 10, "page_index": 0 }
  }'

→ 응답에 voicelist[] 배열 (각 항목: voice/voiceid, gmtcreate, targetmodel, language 등). 이 목록에서 원하는 음색을 골라 합성 호출의 voice 파라미터에 넣으면 프로파일 스위치가 된다 (별도 "활성화" API 없음 — 합성 요청마다 voice 파라미터로 선택).

2-3. 상세 조회 (Query) — Qwen-Audio-TTS/CosyVoice만 지원

{"model": "voice-enrollment", "input": {"action": "query_voice", "voice_id": "yourVoiceId"}}

⚠️ Qwen-TTS(qwen-voice-enrollment)는 이 액션 미지원.

2-4. 업데이트 (Update) — Qwen-Audio-TTS/CosyVoice만 지원

기존 음색을 새 오디오로 갱신 (voice_id 유지):

{"model": "voice-enrollment", "input": {"action": "update_voice", "voice_id": "yourVoiceId", "url": "https://new-audio-url.wav"}}

⚠️ Qwen-TTS는 업데이트 불가 → 음성을 바꾸려면 새 프로파일을 생성해야 함.

2-5. 삭제 (Delete)

# Qwen-Audio-TTS/CosyVoice
{"model": "voice-enrollment", "input": {"action": "delete_voice", "voice_id": "yourVoiceId"}}

# Qwen-TTS
{"model": "qwen-voice-enrollment", "input": {"action": "delete", "voice": "yourVoice"}}

2-6. "선택 사용 / 프로파일 스위치" 사용법 (실제 운영 패턴)

공식 API에는 별도의 "현재 활성 프로파일" 개념이 없다. 매 합성 호출마다 voice 파라미터로 어떤 프로파일을 쓸지 지정하는 stateless 구조:

import dashscope
from dashscope.audio.tts_v2 import SpeechSynthesizer

model = "qwen3-tts-vc-2026-01-22"     # 복제할 때 쓴 target_model과 동일해야 함
voice = "yourVoice"                    # 위 list 조회로 얻은 프로파일 중 선택

synthesizer = SpeechSynthesizer(model=model, voice=voice)
audio = synthesizer.call("오늘 날씨 어때?")
with open("output.mp3", "wb") as f:
    f.write(audio)

→ 여러 프로파일 간 전환은 이 voice 값만 바꿔서 재호출하면 된다. 운영 관리 습관:

  1. list 액션으로 보유 프로파일 목록/생성일 확인
  2. 명명 규칙(preferredname)으로 용도 구분 (예: narrationmale, narration_female)
  3. 1년간 미사용 시 자동 삭제되므로 (아래 쿼터 참조) 장기 보관용은 주기적으로 짧은 합성 요청을 걸어 갱신 필요

4. 감정 표현(Emotion) 지원

Qwen3-TTS 계열은 2가지 감정 제어 방식을 지원한다.

4-1. 인라인 텍스트 태그 (Qwen-Audio-TTS 계열, 실시간 스트리밍 전용)

qwen-audio-3.0-tts-plus / qwen-audio-3.0-tts-flash 모델에서 text 안에 대괄호 태그를 직접 삽입. 단방향 스트리밍 모드만 지원.

제어형 태그 (뒤 문장 전체에 감정 적용, 다음 태그 나오기 전까지 유지):

태그의미태그의미
[sad]슬픔[angry]분노
[excited]흥분[sarcastic]비꼼
[curious]호기심[bored]지루함
[tired]피곤[panicked]공포
[whispers]속삭임[crying]울음
[serious]진지[amazed]놀람
[very slowly]아주 느리게[very fast]아주 빠르게
[asmr]ASMR 속삭임[shouting]외침
[empathetic]공감[mischievously]장난스럽게

富语言(효과음) 태그 (해당 위치에만 삽입, 앞뒤 감정에 영향 없음): [gasp](헐떡임), [sighing](한숨), [laughing](웃음), [giggles](키득), [cough](기침), [clears throat](목가다듬기), [snorts](콧방귀)

사용 예:

[excited]오늘 날씨 정말 좋다! [laughing]우리 같이 나가서 놀자!
[serious]안전 수칙을 꼭 지켜주세요. [excited]자, 이제 시작해볼까요!

4-2. 자연어 지시(Instruct) — Qwen3-TTS 계열

qwen3-tts-instruct-flash-realtime 등 instruct 지원 모델로 교체 후, 세션 파라미터로 자유 텍스트 지시:

qwen_tts_realtime.update_session(
    voice="Cherry",
    instructions="아주 화난 말투로, 말이 빠르게",   # 자유 형식 자연어
    optimize_instructions=True,                    # 지시문 자동 최적화
)

Python 패키지(비 실시간) 버전은 generatecustomvoice()의 instruct 파라미터로 동일하게 사용 (예: instruct="Very happy.", instruct="用特别愤怒的语气说").

⚠️ 감정 태그는 음성 복제(Voice Clone) 음색에는 기본 미적용 — 오픈소스 GitHub 리포 README 기준 instruct는 CustomVoice(사전 정의 스피커) 모델에서 공식 지원되고, VoiceClone은 별도 파이프라인(Voice Design으로 감정 있는 레퍼런스 생성 → Clone prompt로 재사용)이 필요하다고 명시됨. 커뮤니티 포크(gabrielemastrapasqua/qwen3-tts)는 클론 음색에도 --emotion 플래그로 적용 가능하다고 주장하나 비공식.

5. 감정 있는 클론 보이스 만들기 — 공식 권장 워크플로우 (GitHub README)

  1. VoiceDesign 모델로 원하는 페르소나에 맞는 짧은 레퍼런스 클립 합성
  2. createvoiceclone_prompt()로 그 클립을 재사용 가능한 프롬프트로 변환
  3. generatevoiceclone(voicecloneprompt=...)로 실제 콘텐츠 생성 — 매번 특징 재추출 없이 일관된 캐릭터 보이스 유지
design_model = Qwen3TTSModel.from_pretrained("Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign", ...)
ref_text = "H-hey! You dropped your... calculus notebook?"
# → design_model로 레퍼런스 오디오 생성 → create_voice_clone_prompt → generate_voice_clone

7. 검증 메모

  • 위 API 스펙(엔드포인트, 파라미터, 응답 스키마)은 2026-09-03 시점 아리클라우드 百炼(help.aliyun.com/zh/model-studio) 공식 문서에서 직접 발췌·정리함.
  • 코드 예시의 API Key($DASHSCOPEAPIKEY)는 플레이스홀더 — 실제 값 아님.
  • 오픈소스(self-hosted) 경로는 프로파일 관리 API가 공식적으로 없음 — .qvoice 파일 등 로컬 저장 방식은 서드파티 포크(gabriele-mastrapasqua/qwen3-tts, C 구현)에서 --list-voices/--delete-voice로 지원하나 Qwen 공식 리포에는 없음. 프로파일 생성/관리/삭제를 공식적으로 원한다면 百炼 클라우드 API(2번 경로)가 유일한 공식 지원 경로.
