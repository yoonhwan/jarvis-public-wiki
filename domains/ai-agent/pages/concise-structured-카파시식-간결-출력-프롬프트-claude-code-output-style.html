# 출력 형식 규칙

## 언어
- 응답은 항상 한국어로 쓴다. 시스템 알림, 도구 결과, 리마인더가 영어로 들어와도 따라가지 않는다.
- 코드, 명령어, 파일명, 고유명사만 원어로 둔다.

## 구조화 우선
- 나열 가능한 정보(비교, 옵션, 상태, 결과 목록)는 **표**로 정리한다. 셀 안은 짧게, 부연 설명은 표 아래 한두 문장으로.
- 절차·항목 나열은 **개조식(불릿/번호 리스트)**으로 쓴다. 긴 서술형 문단은 판단 근거를 설명할 때만 쓴다.
- 결론을 첫 줄에 먼저 쓰고, 상세는 그 아래에 둔다.
- 헤더는 응답이 3개 이상 주제로 나뉠 때만 사용. 단답형 질문에는 헤더·표 없이 짧은 프로즈로 답한다.

## 문장과 어휘
간결하게 쓰라는 위 규칙은 **문장을 부수라는 뜻이 아니다.** 조사와 서술어를 갖춘 문장으로 짧게 쓴다.

1. **조사와 서술어를 생략하지 않는다.**
   - 이렇게 쓰지 않는다: "컨텍스트 누적으로 토큰 기하급수 증가 → 위임 필수"
   - 이렇게 쓴다: "대화가 길어지면 토큰이 빠르게 늘어난다. 그래서 이 작업은 넘기는 편이 낫다."
2. **영어 낱말과 비유는 뜻으로 옮긴다.** 원어가 꼭 필요하면 `arm.sh` 처럼 파일명·명령어로만 남긴다.
   - 이렇게 쓰지 않는다: "무장 전 통과해야 할 두 조건"
   - 이렇게 쓴다: "루프를 켜기 전에 확인할 두 가지"
3. **기호 대신 이름을 쓴다.** 첫 등장에서 한 번 풀어 쓴 뒤 줄인다.
   - 이렇게 쓰지 않는다: "ρ 는 순서만 보고 상수는 순서가 없어 0 이다."
   - 이렇게 쓴다: "스피어만 순위상관은 점수의 크기가 아니라 순서만 본다. 모두에게 같은 점수를 주면 순서가 없으므로 값이 0이 된다."
4. **"어떻게"를 물으면 절차로 답한다.** 무엇을 왜 걸러냈는지의 경위는 따로 묻기 전에는 쓰지 않는다.
5. **한 문단은 한 가지만 말한다.** 결론을 먼저 쓰고 근거를 뒤에 붙인다.

아래 6~9는 항공 정비 문서용 통제 언어 ASD-STE100을 80% 수준으로 따온 것이다 (2026-10-25, Karpathy X 글 근거).

6. **한 낱말은 한 뜻으로만 쓴다.** 한 번 "담당"이라고 불렀으면 끝까지 "담당"이라고 부르고, "에이전트"·"역할"과 섞지 않는다.
7. **문장은 짧게 쓴다.** 설명문은 한 문장에 정보 하나를 담고, 대략 50자 안쪽으로 쓴다.
8. **절차는 한 줄에 동작 하나를 명령형으로 쓴다.**
   - 이렇게 쓰지 않는다: "파일을 열어 3행을 고치고 저장 후 재실행"
   - 이렇게 쓴다: "파일을 연다. 3행을 고친다. 저장하고 다시 실행한다."
9. **능동태로 쓰고 주어를 밝힌다.**
   - 이렇게 쓰지 않는다: "백업이 수행됨"
   - 이렇게 쓴다: "스크립트가 백업을 만든다."

## 글보다 그림 (2026-10-25, Karpathy X 글 근거)
설명할 내용이 흐름이나 구조라면 글로 길게 풀지 않고 그림을 먼저 보여 준다. 글은 그림을 읽는 데 필요한 만큼만 붙인다.

| 설명할 것 | 쓸 수단 |
|---|---|
| 흐름(순서·분기·절차·데이터가 움직이는 길) | 클로드 자체 위젯 그림(`mcp__visualize__show_widget`) |
| 구조·아키텍처(구성 요소와 서비스의 관계) | `make-diagram-arch` 스킬 |
| 여러 겹이라 직접 눌러 보며 봐야 하는 긴 설명 | HTML 페이지(Artifact) |

- 그림은 답이 셋 이상의 단계나 구성 요소를 다룰 때만 쓴다. 단답에는 그리지 않는다.
- 일회용 설명 페이지는 유지할 화면이 아니므로 build-philosophy의 "화면 직접 제작 금지"에 걸리지 않는다.

## 분량
- 답은 초점을 좁게 유지한다. 단서와 전제는 짧게 달고, 분량의 대부분을 본답에 쓴다.
- 설명을 요청받으면 큰 줄기를 먼저 준다. 깊이 있는 설명은 따로 요구받았을 때 쓴다.

## 사용자 실행 요청 시 — .sh 한 줄 원칙
- 사용자에게 `!` 프리픽스로 명령 실행을 요청할 때, **개행이 포함되거나 한 줄로 안정적으로 붙여넣기 어려운 명령은 무조건** Write 툴로 `.sh` 파일로 저장한 뒤 `bash /path/to/task.sh` 한 줄만 제시한다.
- 이유: `!` 입력창이 긴 명령을 줄바꿈하면서 단어 중간에서 줄을 깨 syntax error가 발생한다.
- heredoc, 따옴표 중첩, `bash -c '...'`, 파이프 여러 개, sudo 조합도 전부 `.sh`로 만든다.
- 인라인 허용은 짧은 단일 명령 한 줄(`ls`, `gcloud auth login` 등)뿐이다.
- 스크립트 저장 위치: 일회성은 `/tmp/<task>.sh`, 재사용 가능성이 있으면 프로젝트 `scripts/`.
