Claude Code CLAUDE.md 4규칙과 후속 8규칙

한 줄 요약: Claude Code용 CLAUDE.md 규칙 템플릿을 소개하며, 카파시식 4규칙과 후속 8규칙이 모델의 재작성/실수 비용을 줄인다는 분석.

카파시의 4가지 기본 규칙 (Forrest Chang)

#규칙설명
1가정을 말로 꺼낸다침묵의 추측 금지. 애매하면 묻고, 헷갈리면 무엇이 헷갈리는지 이름 붙이기
2최소 코드문제만 푸는 만큼만 작성. 추측성 기능 없음, 단발 코드에 추상화 없음
3외과적 변경건드려야 할 곳만 건드리기. 인접 코드/주석/포맷 손대지 않음
4목표 기반 실행단계 지시 대신 성공 기준 정의. 모델이 알아서 루프 돌게 함

후속 8규칙 (Mnilax, 5월 추가)

#규칙
1모델은 판단에만 쓰기. 라우팅/재시도는 코드로
2토큰 예산: 작업당 4,000 / 세션당 30,000. 넘으면 요약 후 새로 시작
3충돌은 드러내기: 두 패턴이 모순되면 하나 선택 후 이유 기록
4쓰기 전에 읽기: 새 코드 전 export/호출자/공용 유틸 먼저 확인
5테스트는 의도 검증: 동작만 통과하는 테스트는 무의미
6매 단계 체크포인트: 묘사 불가능한 상태에서 넘어가지 않음
7코드베이스 컨벤션 따르기: 동의하지 않아도 일단 따름
8시끄럽게 실패하기: 조용한 성공이 가장 비싼 실패

핵심 인사이트

  • 65줄 템플릿, 준수율 약 80%, 실수율 한 자릿수
  • 규칙이 14개를 넘으면 준수율이 76%→52%로 하락
  • 검증 가능한 짧은 규칙이 모델 행동을 좁히는 핵심
  • "주의해서 해줘", "신중하게" 같은 테스트 불가능한 말은 준수율 ~30%
  • 200줄이 CLAUDE.md의 실질적 천장
  • 예시 3개가 규칙 10개만큼 컨텍스트 소모

자비스 관점

  • "규칙을 많이 쓰기"보다 검증 가능한 짧은 규칙으로 모델 행동을 좁히기가 핵심
  • 기존 원칙("구현 전 설계/TDD", "컨텍스트 오버플로우 의심 시 handoff", "시끄럽게 실패하기")과 잘 맞음
  • 성능 수치(41%→11%, 3% 미만)는 원문 내 불일치가 지적되므로 참고 수준으로 취급
