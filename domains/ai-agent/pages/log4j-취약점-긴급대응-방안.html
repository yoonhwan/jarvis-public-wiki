log4j 취약점 긴급대응 방안

📄 원본: [[original.pdf]]

📋 요약

  • Apache log4j2 라이브러리에서 JNDI 인젝션을 통한 원격코드실행(RCE) 취약점 발견 (CVE-2021-44228)
  • CVSS 스코어 10점 — 가장 치명적인 등급
  • log4j2 2.0-beta9 ~ 2.14.1 버전을 사용하는 모든 Java 기반 소프트웨어에 영향
  • 중국 Alibaba Cloud 보안팀 Chen Zhaojun이 2021.11.24 보고

💡 키포인트

  • log4j2는 Java 로깅 프레임워크로, 수많은 Apache 프로젝트에 내장 (Struts2, Solr, Druid, Flink, Kafka 등)
  • ElasticSearch, Flume, Hadoop, Logstash, Spring-Boot-starter-log4j2도 영향권
  • 공격자가 JNDI Lookup을 통해 원격 코드를 실행할 수 있음

🛡️ 대응 방안 (버전별)

① 2.0-beta9 ~ 2.10.0

JndiLookup 클래스를 classpath에서 제거:

zip -q -d log4j-core-*.jar org/apache/logging/log4j/core/lookup/JndiLookup.class

② 2.10 ~ 2.14.1

시스템 설정 변경:

log4j2.formatMsgNoLookups=true
# 또는 환경변수
LOG4J_FORMAT_MSG_NO_LOOKUPS=true

③ 모든 버전 (권장)

최신버전 2.15.0 이상으로 업데이트:

  • 다운로드: https://logging.apache.org/log4j/2.x/download.html
