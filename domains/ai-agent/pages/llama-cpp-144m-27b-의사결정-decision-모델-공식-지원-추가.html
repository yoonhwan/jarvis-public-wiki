핵심 요약 (원문: HuggingFace Blog, ggml-org, 2026-10-02 게시)

llama.cpp 서버가 /v1/systemone 엔드포인트를 통해 decision model(의사결정 모델)을 지원한다. 상태(state: 텍스트/JSON/스크린샷)와 타입이 지정된 질문들을 보내면, 모델이 텍스트 생성 없이 각 옵션의 확률값을 한 번의 forward pass로 반환한다.

Decision model이란? 옵션들을 스코어링해서 답하는 모델. 챗 모델은 출력 토큰마다 forward pass가 들고 출력을 파싱해야 하지만, decision model은 입력을 한 번 읽고 항상 주어진 옵션 중 하나를 확률과 함께 반환한다. 용도: 요청 라우팅, 콘텐츠 모더레이션, 에이전트 스텝 검증, 다음 행동 선택.

API는 TypeSafe의 Jev 모델이 도입한 System One 포맷을 따르므로, 기존 클라이언트는 base URL만 바꾸면 된다. 구현 세부사항은 PR #29818.

Quick Start

llama serve -hf ggml-org/Kev-4B-GGUF

세 가지 질문 타입:

타입보내는 것받는 것
choice옵션들 (설명 선택적)최상위 옵션 + 옵션별 확률
score2~10단계 레벨 (낮은순)예상 레벨 (두 단계 사이값 가능)
noulYes/No 질문Yes일 확률

이미지 입력 (OpenJev)

일부 모델(현재 OpenJev)은 문서/스크린샷 같은 이미지도 읽을 수 있다. Vision projector는 자동 다운로드됨:

llama serve -hf ggml-org/OpenJev-GGUF
import base64
import requests

with open("document.png", "rb") as f:
    image = "data:image/png;base64," + base64.b64encode(f.read()).decode()

response = requests.post("http://localhost:8080/v1/systemone", json={
    "state": "A file uploaded by a customer.",
    "images": [image],
    "questions": {
        "kind": {
            "type": "choice",
            "instructions": "What kind of document is this?",
            "criteria": {"invoice": None, "receipt": None, "contract": None, "other": None},
        },
    },
})

print(response.json()["answers"]["kind"]["choice"])  # invoice

state는 chat message 리스트도 가능하며, data URL 형태의 image_url 파트는 동일하게 이미지로 읽힌다.

멀티 모델 라우터 모드

llama serve
curl http://localhost:8080/v1/systemone \
  -H "Content-Type: application/json" \
  -d '{"model": "ggml-org/Julia-1-GGUF:Q8_0", "state": "...", "questions": {...}}'

/v1/models로 로드된 모델 id 목록 확인 가능. 모델 1개만 로드된 경우 model 필드는 무시됨.

운영 팁

  • 여러 크기의 모델을 시도해보기: 작은 모델=빠름, 큰 모델=더 많이 안다. Decision Index로 비교.
  • 옵션을 설명과 함께 제공: Julia-1은 레이블만 주면 "충전 2회" 티켓을 shipping으로 잘못 라우팅했지만, 옵션에 설명을 추가하자 billing(0.99)으로 정확히 분류.
  • 모델별로 confidence cutoff를 따로 설정: 모호한 티켓("Hi, quick question about my account")이 Julia-1에서는 0.25, Kev-4B에서는 0.80으로 나왔음 — 모델마다 보정 필요.
  • 질문을 배치로 묶기: 질문들은 독립적으로 답변되며, Kev-4B/lev/OpenJev는 state를 한 번만 처리.
  • 다양한 quantization 시도: 일반 GGUF와 동일하게 여러 precision 제공 (예: llama serve -hf ggml-org/Kev-4B-GGUF:Q8_0).
