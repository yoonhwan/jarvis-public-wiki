Qwen3.8 MTP 드래프트 어휘사전 — 한국어 디코딩 +54%

Threads: @pyjinnode (pyjinnode, 매일 AI 소식 1차 출처 확인 계정)

본문 (Main Post)

초당 16.9토큰 → 초당 26.1토큰, +54%.
Qwen3.8의 한국어 답변 디코딩을 높이는 MTP 드래프트 어휘사전이 공개됐다. 한국어 위키백과를 바탕으로 토크나이저 가족별 파일을 만들고, 같은 장비에서 적용 전후를 측정했다.

댓글 스레드 (작성자 추가 내용, Author)

원리는 드래프트 헤드가 계산할 어휘를 빈도 상위 부분집합으로 줄이는 방식이다. 검증은 전체 어휘로 진행해 출력은 그대로 두고 드래프트 계산을 줄인다.
바로 적용 가능한 모델은 nvidia/Qwen3.8-Flash-Next-NVFP4 하나이며, 지원 엔진도 vLLM뿐이다.
드래프트당 수락 토큰은 1.33 → 2.16이었다. 대체 문자와 한국어 스크립트 오염은 0개였고, 기억 능력 문항은 12/12로 영향이 없었다. 라이선스는 Apache-2.0이다.
세나 평: 측정값과 미측정 범위를 갈라 적은 점이 실무 검토에 맞다.
(링크: github.com/veneta-ai/mtp-draft-vocab-ko)

원리

  • 방식 이름: FR-Spec (ACL 2025) 기반 — MTP 드래프트 헤드가 "빈도 상위 부분집합" 어휘만으로 출력 투영을 계산
  • 검증(verification)은 항상 전체 어휘로 진행 → 출력 결과는 완전히 동일, 드래프트 계산 비용만 절감
  • 기존 배포된 부분집합은 영어·코드 기준이라 한국어 토큰이 빠짐 → 한국어 드래프트가 자주 거절되어 느려짐
  • 이 레포는 한국어 위키백과 기반으로 토크나이저 가족별 65,536개 토큰 어휘 파일 제작

적용 가능 모델/엔진 현황 (2026-10-07 기준)

모델군구조상태
Qwen3.8-Flash-Next (nvidia 체크포인트)자체 MTP 헤드 + nvidia가 이미 패치한 gettoptokens()측정 완료, 바로 사용 가능
Llama 3.1 8B + EAGLE-1별도 드래프터 모델gettoptokens() 범용 패치로 실측 완료 (+13.4%)
EXAONE 4.5 / GLM 5.3 Flash / Llama 3.3 70B+EAGLE-3gettoptokens() 없는 표준 경로 확인됨패치 필요, 2차 검증(EXAONE) 진행 중
Qwen3-Next미확인 체크포인트미확인
DeepSeek V4/V4.1 Flash별도 "DSpark" 드래프팅 방식이 패치 대상 아님 — 별도 조사
Gemma 4 + 어시스턴트 드래프터체크포인트 내장 centroid projection 방식이 패치 대상 아님 — 별도 조사

엔진 지원: 현재 vLLM뿐. Ollama/LM Studio가 쓰는 llama.cpp는 Qwen3.8-Flash-Next MTP 헤드 로딩(--spec-type draft-mtp)은 최근 지원됐지만 어휘 축소 기능 지원 여부는 미확인. SGLang은 --speculative-token-map이 있으나 EAGLE-2 전용이라 호환 안 됨(파일 포맷도 다름, .pt 텐서 vs 순수 정수 리스트).

선행 연구 (Prior Art, 2026-10-07 레포 업데이트)

  • vLLM 이슈 #58578 (akapug, 2026-09-24): 같은 아이디어를 먼저 제안, Intel Arc + Qwen3.5 계열로 +25~29% 측정
  • vLLM PR #59740 (stecasta, "Context Aware Sparse LM Head", 2026-10-02 오픈, 미병합): 고정 32k + 토큰별 rank-256 SVD로 고르는 16k를 더하는 더 정교한 구현. 같은 모델·하드웨어로 측정한 수치가 +15.2%(BF16)/+22.6%(NVFP4)로 veneta-ai의 +54%와 상당히 다름 — 원인 미확인(프롬프트 구성/동시성/정적·동적 선택/기준선 차이 등 후보)
  • veneta-ai 레포는 PR #59740이 건드리지 않는 구형 범용 MTP/EAGLE 파일(eagle.py, exaone45mtp.py, glm4moemtp.py, deepseek_mtp.py)을 다루는 보완 관계 — 중복 아님
