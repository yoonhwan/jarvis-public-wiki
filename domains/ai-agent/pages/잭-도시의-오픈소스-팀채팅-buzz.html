잭 도시의 오픈소스 팀채팅 "Buzz"

트위터 만든 사람이 이제 팀 채팅까지 다시 만드는 이유, 기능이 아니라 종속 문제.

잭 도시(Jack Dorsey)가 Slack 쓰는 게 지겨워서 아예 새로 만든 오픈소스 팀 채팅 Buzz. 런칭 트윗에 밝힌 이유는 "Slack과 Github 의존도를 줄이려고 만들었다."

본문 (Main Post)

잭 도시가 Slack 쓰는 게 지겨워서 아예 새로 만들었습니다. 이름은 Buzz, 오픈소스 입니다.

런칭 트윗에 이유를 직접 적어놨습니다. "Slack과 Github 의존도를 줄이려고 만들었다." 트위터 만든 사람이 이제 팀 채팅까지 다시 만드는 이유는 기능이 아니라 종속 문제입니다.

댓글 스레드 (Reply Thread — 작성자 추가 내용)

1. 겉모습은 Slack, 차이는 두 가지

겉모습은 Slack입니다. 채널 있고, 스레드 있고, DM 있고. 다른 건 두 가지.

차이점내용
AI 에이전트 = 정식 멤버봇이 아니라 정식 멤버. 사람 계정 빌려 쓰는 게 아니라 자기 계정, 자기 암호키, 자기 권한을 따로 받음. 채널 초대 방식도 동료 초대와 동일
Git 호스팅 내장채팅, 코드 리뷰, 에이전트 작업이 한 창에서 돌아가는 구조

Claude Code, Codex, goose 전부 붙습니다. 모델 안 가려요.

2. 핵심은 소유권 (Ownership)

Slack에 쌓인 몇 년 치 데이터는 다른 데로 못 옮깁니다. 그래서 다들 그냥 눌러앉죠. 모델 접근도 마찬가지.

원문 필자의 지적:

  • 오늘 월 $200인 무제한 요금제가 내일 얼마가 될지 모름
  • 출시 며칠 만에 회수되는 모델도 실제로 봤음
채팅도 모델도 남의 손에 있으면, 그 위에 세운 사업도 남의 손에 있는 겁니다.

Buzz의 답은 셀프호스팅. 대화, 파일, Git 원격저장소가 전부 내가 돌리는 릴레이 서버에 남습니다. 로컬 모델 받아서 팀이 나눠 쓰는 공유 컴퓨트 기능도 제공.

3. 사용자 Vinny의 워크플로 루프

팟캐스트에 나온 사용자 Vinny의 루프:

  1. 팀 트윗 리더보드 앱을 에이전트한테 시켜서 만듦
  2. 그 앱에 공개 API를 뚫음
  3. 매일 수치를 채널로 끌어오는 워크플로를 걸음
  4. 다이제스트에 답장으로 에이전트한테 질문: "최근 7일 잘된 트윗들의 공통점이 뭐야?"

→ 앱으로 나간 정보가 다시 에이전트 컨텍스트로 돌아오는 순환 구조.

Slack에서 같은 걸 하려면 API 토큰에 플랫폼 앱에 공부할 게 한가득인데, 여기선 도구 연결이 15분이면 끝난다는 게 그의 설명.

4. 솔직한 현재 상태 (베타/알파)

솔직히 지금은 베타, 어쩌면 알파:

  • 워크플로는 거칠고
  • 속도는 Claude Code보다 느리고
  • 모바일 앱은 아직 작업 중

그런데 이 제품이 드러낸 사실 하나는 이미 유효합니다:

팀 채팅은 어느새 컨텍스트 저장소가 됐고, 최고의 아웃풋은 컨텍스트를 가장 많이 쥔 쪽에서 나옵니다.
그 저장소를 남의 서버에 둘 거냐, 내 서버에 둘 거냐 — Buzz가 던진 질문은 이겁니다.
