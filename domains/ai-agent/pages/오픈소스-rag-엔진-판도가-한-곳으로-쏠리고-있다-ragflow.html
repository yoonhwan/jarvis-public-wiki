오픈소스 RAG 엔진 판도가 한 곳으로 쏠리고 있습니다.

RAGFlow가 스타 8만8천을 넘겼고, 오늘 하루만 +474로 GitHub Go 트렌딩 1위에 올랐어요. 오래 쓸 만한 이유 4가지를 뜯어봤습니다.

오래 쓸 만한 이유 4가지 (Reply Thread)

1/ 문서를 의미 단위로 쪼개고, 답변마다 원문 위치를 찍어준다

Word, 슬라이드, 엑셀, 이미지, PDF를 그대로 넣으면 구조를 분석해 템플릿 청킹을 돌립니다. 인용 위치가 화면에 보이니까 모델이 지어낸 답을 사람이 바로 잡아낼 수 있어요.

2/ DeepSeek v4, Gemini 3 Pro, GPT-5 계열을 설정만 바꿔서 교체

임베딩 모델도 같은 방식으로 갈아끼웁니다. RAG 붐 초기 프로젝트 상당수가 모델 지원이 늦어 도태됐는데, 여기서는 새 모델이 나와도 파이프라인을 처음부터 다시 짤 필요가 없습니다.

3/ 검색·응답을 넘어 여러 단계 에이전트 워크플로우 구성

MCP로 외부 도구와 에이전트를 연결하고, Python과 JavaScript 코드 실행기 컴포넌트도 내장돼 있어요. RAG 따로 에이전트 프레임워크 따로 두던 구성이 하나로 합쳐지는 지점이네요.

4/ Confluence, S3, Notion, Google Drive 데이터를 자동으로 끌어온다

에이전트가 대화와 작업 맥락을 기억하는 메모리도 붙어 있고, Discord와 Telegram, Line 채널로 내보내는 것도 됩니다. 사내 문서가 흩어져 있어도 수동 업로드 없이 지식베이스를 굴릴 수 있다는 뜻이죠.
